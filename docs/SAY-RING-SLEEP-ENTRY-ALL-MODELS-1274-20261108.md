# 睡眠查看入口统一：所有型号

## 基线与实际原因

- 先核对独立仓库`tangwu88/SayRing`、远端与干净工作树，`git fetch --prune origin`后，在XR实际安装的iOS1263分支执行ff-only更新，仍为`226badef9ba903182a57d32d2ae82a9b4decb2a0`。新建`codex/r7y-sleep-overview-1274-20261108`，未覆盖其他工作树、Android1273、Harmony或Google Play分支。
- 原生`CoolWearModel`与Dart分类器均已把R7y识别成R7Y；iOS握手可以确认历史通道，但睡眠指标仅在有效睡眠批次/结束包后加入。旧首页入口额外兜底仅列R7Pro、HR05、R7Ultra，因此漏掉R7Y。新增测试在旧代码找不到`home-sleep-overview-entry`，真实复现入口缺失。
- 最初补R7Y的阶段通过双时区各2065项；用户扩大要求后，此方案不作为最终交付，最终入口不再查询型号或采集能力。另一个新规则测试在旧入口条件下得到false，再次确认旧行为与新要求冲突。

## 最终修改与数据边界

- `lib/services/app_controller.dart`：`canOpenSleepOverview`仅保留既有版本睡眠显示范围；不依赖型号、通道、当前连接、能力就绪或首个睡眠包。活动的原型号兜底没有扩大，其他健康卡与手动测量能力判断不变。
- `lib/ui/pages/dashboard.dart`：没有睡眠记录时只显示“暂无睡眠记录”，查看最近一次/按日期的操作不变。
- `lib/ui/sleep_detail_widgets.dart`：未连接、能力未就绪、历史不可用时仅引导查看其他日期，不建议执行不可用的同步。打开入口只读既有加密记录，不能因入口可见就增加原生能力、下发设置、清空、初始化或测量命令。
- 现有`healthUiOwnerKey`仍同时包含环境、稳定账号与精确戒指；完整睡眠库查询继续核对登录代次与目标，缺失数据不填零、不补分期。没有改动数据库结构、戒指设置、云端接口或账号登录。
- `AGENTS.md`、回归清单与复盘已记录最新规则，避免后续又通过扩型号白名单修复同类问题。
