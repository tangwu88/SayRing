## 问题与修复

- **P1：已保存的精确目标未发起自动重连。** 复现条件：当前账号已确认的 QRing 戒指 UUID 正确，iOS 系统可取回该外设、蓝牙可用，但 `CBPeripheral.name` 暂时为空。预期是继续连接同一 UUID 并重新完成厂商握手；原 `startAutomaticRecovery` 因名称为空直接跳过，没有发出连接请求或等待状态。此问题由真实生产方法的合成原生夹具复现，不声称 XR 的前次自然断连已经证明触发了这一条件。
- 在 `ios/Runner/QRingWearableBridge.m` 中，对**已由当前 owner、UUID、已验证名称和恢复上下文**限定的自动恢复，允许当前系统名称为空时使用保存名称继续精确目标连接；当前系统名称非空却不属于该厂商通道时仍拒绝。不能凭名字连接其他戒指，也不改变首次选择、手动扫描或绑定。连接成功依然以真实 SDK 能力握手完成为准。
- `tool/fixtures/qring_recovery_state.m` 与 `tool/qring_recovery_state.test.mjs` 增加无名称精确目标、无效保存名称和当前名称冲突三种断言。修复前无名称用例失败，修复后通过。已有无线失败、SDK 失败、取消、换 owner、蓝牙关闭与恢复反例继续通过。

此前 1196 五轮手动重连中位 2.48 秒；1200 后续静置曾在约 4 分钟断开且超过 2 分钟未恢复，见 [1200 记录](SAY-RING-AUDIT-XR-R8-1200-20261031.md)。本轮修改针对一条代码死路，**不**把它描述成所有断连的原因或保证永久连接；先前的系统 code 6 和弱信号仍需新的实物证据区分。
