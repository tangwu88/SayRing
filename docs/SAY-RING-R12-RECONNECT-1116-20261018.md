## 现场与失败记录

iPhone 15 Pro Max 最初可用，实际安装 cn.saydian.ring / 1.0.2（1115）。精确 Profile VM PID 与原生进程匹配，当前账号仍在恢复原 R12，未同步/测量，未收到新握手。系统通知横幅使自动化来源暂时显示 SpringBoard，不据此误判 App 被占用；实际设备页仍显示等待靠近。

首个 LLDB 批处理在设备异步附加尚未停止时执行表达式，失败后目标进程结束，未操作容器。正常重新启动 Profile，日志于北京时间 17:55:22 请求连接、17:55:29 报告 QRing transport connected；这是传输成功，不等于能力或测量成功。

第二次交互附加等待到 SIGSTOP 后，表达式先因 Objective-C 返回类型声明失败，随后寄存器/堆栈读取失败，未取得可信原生属性；脱离调试又报告 Sending disconnect packet failed。随后 WDA / VM 同时断开，usbmux 返回空、CoreDevice 所有 iPhone unavailable / error 1011；本轮尚未确认是物理断开还是手机重启，不将此诊断失败冒充 App 自发崩溃或戒指故障。

本轮私有助手曾有 URL 路径未解码、Node 顶层 await 与 require 混用、旧文件名 glob 无匹配等失败，已局部修正；都不是生产 App 故障。原始日志、屏幕和健康信息只留忽略的私有目录，不进 Git。手机离线后停止测量和安装尝试，未清绑定或改监测设置。

## P1：重连实际取消路径漏掉真实状态协调

复现路径：设备页“重新连接” → QRing disconnectWithResult → QCCentralManager.remove。当前 remove 在 Connected / Connecting 时发取消并置 Disconnecting，但漏掉 disconnect 已有的 reconcileCancellation；缺少 CoreBluetooth 终态回调时，即使无线状态已实际断开，桥接取消屏障也可能不解除。Disconnecting 还会落入立即成功分支，未证明真正断开。

预期：两个取消入口均以同一代次、同一外设和实际 Disconnected 状态完成清理；仍在 Connecting / Connected / Disconnecting 时不因超时假装成功。真正解绑后的终态为 Unbind，有原生绑定时为 Disconnected；账号持久绑定及健康数据不变。

先在实际接线回归中补 remove 分支、正在断开和终态语义断言，记录红测后最小修复。该代码缺陷已由调用路径确认，但现场断开前未取得原生取消属性，不能先断言它就是本次 R12 等待的唯一根因。后续测试、构建及实物结果另记。

## 最小修复与软件验证

`QCCentralManager.m` 的 remove 将 Disconnecting 纳入等待真实取消的分支，并调用既有同代次/同外设协调；协调后按原生绑定是否仍在返回 Disconnected / Unbind，不再把解绑误报成仍绑定。保留原取消屏障，不按等待时长强行释放，也不增加扫描、任意历史自动连接或数据清理。

实际接线回归先失败于缺少 Disconnecting 分支；修复后的首次绿测因源码注释插入打断过紧正则而失败，改为仅移除行注释后检查同一调用顺序，不删断言。最终增加直接编译实际 remove / disconnect / reconcile 方法的 Foundation 合成无线夹具：48 项断言通过；去掉 remove 协调调用的反例真实执行失败，证明不是单靠文本匹配通过。它仍不是 CoreBluetooth 或真实戒指验收。

修复仅涉及上述原生文件、回归测试/夹具和 CI 接线；原有 iOS job 在已做 CoolWear 检查的位置加入 QRing 取消回归，使新行为夹具也在 macOS CI 执行。未改 Dart 业务、厂商原包、账号/绑定格式、健康数值、服务器或审核。

本机空间不足时，先确认无 iOS 构建或目录句柄，再对两份生成 Debug Runner.app 各 223 文件逐项 SHA-256 核对与保留的 1115 冻结包一致；仅删除这两个可重建副本，实际可用空间从约 253 MiB 升至 603 MiB。原源码、SDK、签名包、dSYM、安装包和手机备份均保留，没有清理其他项目。

格式 240 文件零变化、静态分析零问题；原生/包装/保数据门禁 45 项、主机契约 503 项、发布工具 Python 35 项通过。夹具输出的取消失败、正式发布/签名等文案是合成测试，不是设备失败、实际生产发布或新正式包。

首次 UTC 全量停留于 39 项后无进展，已对本任务测试进程发 SIGINT，中断结果不算通过；后续检查旧 PID 已退出，针对旧 PID 的 TERM 返回不存在，未影响其他任务。原组合命令随后启动上海全量，因此不依据组合命令退出码把 UTC 当成功；待独立重跑 UTC 并核对两份实际最终测试数。

后续上海全量实读 `All tests passed` / 1312（1分39秒）；UTC 独立 `--concurrency=1` 重跑实读 1312（2分13秒）且退出0。两轮均传入正确生产 origin `--dart-define=SAYDIAN_API_BASE_URL=https://app.saydian.cn`。新原生测试/反例重新合入45项门禁全部通过，Node 语法、Actionlint 和 diff 检查通过；未用中断的39项冒充UTC通过。

本轮 VM forward、mDNS 和日志采集已停止，仅本任务拥有的进程被处理，未终止其他调试任务或原有 WDA。usbmux / CoreDevice / IOUSB 三处复核均没有在线 iPhone，已发一次非阻塞重接解锁提示；没有手机时不反复尝试测量、安装或声称新包已在实物运行。
