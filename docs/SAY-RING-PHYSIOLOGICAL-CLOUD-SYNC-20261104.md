# 生理记录账号云同步

日期：2026-11-04。修改前基线 `7854168ad65988ea99438e4d95cbdfe2dec6d9f7`，当前分支与远端同名分支一致，工作区干净，已 fetch。

## 需求与原因

用户先要求检查测量数据上报，随后明确要求血压、心率、血氧等也上报云端，并确认全部按新规则执行，**不增加“生理数据云同步”开关**。此前只读审计确认 XR 当前账号66条生理记录因旧 iOS 上传策略留在本机，不是已证实的服务端丢数。

复现：iOS账号连接兼容戒指，保存有效心率/血氧等记录后发起同步。预期为当前账号真实记录自动上云；实际旧 `HealthSyncService` 与 API 同时按活动/睡眠投影过滤，生理行一直待同步。影响等级 P1，现象是账号云端缺少本机测量。

## 实现范围

- 独立 `HealthCloudUploadPolicy` 仅扩展账号上传：活动、睡眠、血压、心率、血氧、HRV、皮温。不使用读卡片开关扩大测量能力，不增加开关或伪造测量。
- iOS控制器队列与实际V2上传接口都使用同一新规则；Android保留其既有真实指标上传路径。
- 保存原ID、指标、值、单位、来源、质量与时间；血压保留收缩压/舒张压，HRV保留原SDK验证依据，皮温不能改称核心体温。
- 旧有效待传记录可补传；无效/未来隔离行不复活，游客和他人共享记录不上传。波形不静默丢弃后标成功；只按服务器逐条回执标同步。
- 公开说明应增加新构建适用范围，保留旧构建限制与已审v3正文/同意版本，避免协议配对变化导致登录故障。本轮不提交App Store、不改变下载清单。
