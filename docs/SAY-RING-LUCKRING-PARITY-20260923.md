## Bug 报告与实施范围

### P1：活动数据同步后不可见

- 复现：HR01 同步日常活动后打开健康页底部运动区。
- 预期：显示今日步数、距离、热量及目标进度。
- 实际：原生映射已有三项数据，但 `_TodayHealthOverview` 被明确标记为隐藏且没有页面入口。
- 影响：用户无法确认戒指的基础活动数据是否成功同步。

### P1：HR01 运动入口与命令被额外门禁

- 复现：连接完成后，功能位回调延迟或缺失时进入运动区，或尝试开始运动。
- 预期：在真实设备信息握手和厂商能力响应后展示支持模式，并可下发运动命令。
- 实际：运动模式和命令都额外要求 `functionControl != null`；能力读取超时会清空入口，命令直接报未连接，且只接入 5 类模式。
- 影响：运动核心流程不可用或与 LuckRing 能力明显不完整。

### P1：真机结束运动长时间卡在“正在保存”

- 复现：真机连接 HR01，启动“步行”后点击结束。
- 预期：结束命令返回后立即保存 App 本地记录，历史数据拉取不阻塞用户操作。
- 实际：`stopSport()` 同步等待厂商全量历史同步，未收到同步结束回调时需等待 30 秒超时；本地保存又触发一次历史读取。
- 影响：用户会认为结束按钮或运动功能失效。

## 计划修改

- 恢复今日活动概览与目标设置入口；无记录时显示 `--`，不补零。
- 保留设备信息真实握手门禁；功能位用于健康指标细分，HR01 协议已确认的活动、睡眠和运动能力在成功握手后可用，并继续异步读取功能位更新心率、血氧、HRV、体温。
- 补齐视频首屏且 SDK 已确认的 12 类运动，保留现有徒步；同步记录按 SDK 类型精确映射，未知类型继续跳过。
- 增加原生与 Flutter 回归，并执行格式化、静态分析、双时区全量测试、Android 原生测试、Debug/QA Release 构建及可执行真机检查。Windows 无法执行 iOS 构建，须明确保留。

## 执行与验证记录

### 实施结果

- 恢复健康页今日活动卡，显示步数、距离、热量与目标进度，并接入已有目标设置页。无数据时显示 `--`，不把未知值写成 0。
- HR01 完成真实设备信息握手后，开放步数、距离、热量、睡眠以及厂商协议已确认的运动基线；心率、血氧、HRV、体温仍由戒指返回的功能位单项开启。
- 补齐 13 个运动入口及 SDK 精确类型映射：跑步、室内跑、步行、骑行、室内骑行、篮球、足球、羽毛球、游泳、跳绳、瑜伽、徒步、登山。历史记录未知类型仍跳过，不猜测。
- 户外跑、步行、骑行、徒步、登山保留手机前台轨迹；室内和球类等项目不再误开 GPS。
- 结束运动不再同步等待厂商全量历史；本地记录保存后直接合并到当前列表，进入运动记录页或手动刷新时再拉取戒指历史。

### 过程中失败与修复

- 首次页面回归把运动区直接放入独立 `DashboardPage` 测试，因缺少 `Material` 祖先失败；测试容器改为真实 AppShell 同等的 `Scaffold` 后通过。
- 今日活动卡首版无条件显示，导致断开状态的底部提示回归失败；改为有本地记录或已连接且能力支持时显示。
- 真机首轮运动能启动、计时和记录定位点，但结束卡在“正在保存”；定位到同步历史的 30 秒阻塞后拆分本地保存与设备历史刷新，并新增回归保证 App 主动结束不会立即再拉取全量运动历史。
- 直接执行 Release 构建被 `verifySaidianReleaseMode` 拒绝，原因是未声明生产或 QA 模式；本轮不使用生产密钥，改用 `SAIDIAN_ALLOW_QA_RELEASE=true` 后构建通过。
- 尝试用 PowerShell 删除被 Git 忽略的 `build/` 视频抽帧、FFmpeg 与真机截图临时件时，命令被当前执行策略拒绝；这些文件未进入 Git，不影响源码和 APK，但本轮未能自动清理。
- 首次提交因本机未配置 Git 作者身份而被拒绝；核对本仓库近期历史后，仅在当前仓库配置与既有提交一致的 `Codex <codex@openai.com>`，未修改全局 Git 账号。
