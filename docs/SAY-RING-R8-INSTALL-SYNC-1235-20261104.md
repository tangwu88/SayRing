初始源码为干净的 `codex/integrate-latest-20261031`、`9ede579cb3177b1e56514947fed3f5961f430632`，最新功能提交为 `eef818e`。先前 fetch 已确认同步；交付前再次 `git fetch origin --prune` 发现仅增加两项文档提交 `6def5bc`、`2c3c5c0`，核对 diff 仅 3 个 docs 文件后安全快进至 `2c3c5c0`。本轮没有修改产品源码或构建配置。

## 实测与证据边界

所有时间来自正常触摸、页面状态及计时，不修改运行时字段，不伪造 SDK 回执。

| 场景 | 观察结果 |
| --- | --- |
| 原正式 1231，手动同步 | 按下至按钮恢复约 46.3 秒；观察忙状态约 43.2 秒，进度持续推进，连接保持 |
| 新源码 1235 诊断包，手动同步 | 约 48.9 秒；观察忙状态约 46.0 秒，进度至 98% 后结束 |
| 新源码 1235 诊断包，结束进程后正常重开 | 未点重连或同步，约 10.1 秒已连接且同步中，启动后约 56.5 秒同步结束 |
| 1235 诊断包，再次手动同步 | 约 45.2 秒；实际出现“数据同步完成”，无部分同步提示 |
| 最终正式 1235，结束进程后重开 | 未点同步/重连；约 5.7 秒已连接且同步中，启动后约 49.3 秒结束，绑定保留 |
| 最终正式 1235，自动完整读取后手动刷新 | 约 12.6 秒，观察忙状态约 10.1 秒；实际出现“数据同步完成” |
| 最终正式 1235，再次手动近期刷新 | 约 13.9 秒，观察忙状态约 11.3 秒；进度推进后恢复同步按钮，连接保持 |

健康数据总览和心率分析页实际打开。当前界面显示的记录数在后续同步前后有增加，但该计数经过当前戒指优先、发布门禁、异常未来日期等投影，不能把它当作整个加密数据库的总行数，也不能据此证明所有新增行都无重复。旧设备未连接时与 R8 连接后的显示数不可直接用来断言历史丢失。

本轮确认普通 R8 在恢复连接后会自动读取，无需用户每次点击同步；完整读取约 45～49 秒，最终正式版在完整读取后的近期刷新约 12.6 秒。源码仅在历史范围真实完成并持久化后采用 2 天近期窗口，首次/检查点失效时仍读取完整范围；不是跳过未完成记录来加速。诊断包前轮耗时不能替代最终正式版的短刷新结果，也未将每次都承诺为 13 秒。完整历史是否与原厂逐项一致、所有 owner 的既有记录及重复行审计、云端逐条对应仍未验收。

尝试连接诊断会话以只读核对入库状态时，自动审批拒绝了该操作，未提供具体原因。停止该路径，没有拆分命令、修改系统安全设置或绕过限制；改用正常页面和包管理状态检查。临时诊断包已被同源码正式包覆盖。

## 回归失败与未验收项

完整 Flutter 两轮（`TZ=UTC`、`TZ=Asia/Shanghai`，均 `--concurrency=1 --dart-define=SAYDIAN_API_BASE_URL=https://app.saydian.cn`）各 **1984 通过、5 失败**，不能写成全量通过。原失败日志均保留，未为了通过修改产品过滤或跳过断言：

1. `qring_dashboard_visual_test.dart`：`home sums the full saved day beyond the recent record cache`。
2. `ui_shell_test.dart`：`activity overview never labels yesterday values as today`。
3. 同文件：`home sleep entry opens real stages and the same dated trend`。
4. 同文件：`sleep trend exposes SDK stages without inventing REM`。
5. 同文件：`QRing sleep stages and score display only returned values`。

第 1 项测试用当天午夜之后 256 分钟生成数据，当前宿主只显示 121/137 条而不是预期 200；其他失败涉及当天固定时段/睡眠测试资料。根据夹具与现有未来历史过滤，执行时刻/时区相关性需要另行用固定时钟复核；本轮未修改全局时间、未降低未来数据隔离。此问题未证明为 R8 无线同步失败，也不能直接忽略。

iOS、HarmonyOS 构建与实机、其他戒指型号、全量数据库去重及厂商数据一致性未执行。最终界面仍为普通 R8 已连接、同步按钮可用，正常进程仍在；留在用户可用的正式版设备页。
