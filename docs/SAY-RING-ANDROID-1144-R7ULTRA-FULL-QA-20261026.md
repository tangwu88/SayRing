## 问题清单与复现

### Q1 — P1：R7 Ultra 完整历史同步仍未确认

复现：连接目标 → 设备页点击同步 → 连续采样，期间不发送其他 BLE 指令。预期：厂商完整终态与历史读取范围得到确认，或明确失败/保留部分记录。实际：第二轮最终显示“已更新 3 条，戒指尚未确认完整同步；已有记录已保留”，约 40.9 秒采样见终态，前次 37.6 秒仍等待。数据接收与完整性是两回事，不能缩短等待或静默改成功掩盖问题。

首轮非连续采样曾看到接收 3 条，后续跨页面返回时同步按钮已恢复，没有捕获其终态。中途用户提示中提到“数分钟”的等待仅对应稀疏 UI 观察，不能作为精确耗时或已证明超时机制失效；以第二轮连续计时为可复现结论。没有已知戒指内历史存量或清理回执，不能据此断言历史丢失。

建议后续：在原签名受控诊断版本中记录不含健康值/身份的阶段、ACK、历史结束回调，核对该固件厂商 SDK 契约。保留已收到记录、去重和未知值，不缩历史范围。

### Q2 — P1 待验：短时室内运动未收到实时数据

复现：连接目标 → 室内跑 → 开始 → 约 48 秒后结束。预期：在设备实际支持并有有效回调时显示心率等数据；未知值保持未知。实际：计时正常，但距离、步数、实时心率、配速、热量一直为“--”。静止短时测试不足以判断所有运动指标必然应产生，也不能确定是固件、SDK 回调还是映射问题；本轮不能验收实时运动正常。

另：进入运动记录后先显示“戒指中暂无运动记录”，稍后跨页出现“戒指暂未返回运动记录；已有记录仍可查看，稍后可重试”。未确认/超时不等于确定空历史，建议独立展示读取中、确实空、部分读取和失败，避免迟到提示干扰其他页面。

### Q3 — P2：运动缺失指标补零并展示为已记录

复现 Q2 后打开保存记录。实际列表以距离/千卡数值展示，详情显示距离；而前台未收到这些实时值。只读源码核对 `lib/ui/pages/sports.dart` 的 `_finalizeSport` 保存分支：缺失 `calories/steps/heartRate` 通过 `?? 0` 保存，未收到距离时回退 `_routeDistanceKm`，本次室内无轨迹。预期：未知指标不冒充真实零，明确区分仅本地计时与戒指有效数据。此项有具体源码依据；本轮按诊断边界**未直接修复**。

### Q4 — P1 业务阻断待定因：订单不可用

复现：我的 → 我的订单 → 全部。实际显示“此功能暂时无法使用，请稍后再试”，不是正常空订单状态。商品目录和空购物车可读，不能说明订单业务接口也可用。需进一步在授权会话下核对具体订单响应、配置和服务日志；本轮没有导出 Token 或擅改后台开关，根因未定。

### Q5 — P2 待复现：首轮心率/血氧超时，复测成功

首次两个独立测量均在 75 秒窗口后出现“长时间未检测到有效结果”，未保存当日记录。充电唤醒之后用户再次确认佩戴贴合，后续两项均成功；因此保留初轮失败，但不能声称已证明在相同佩戴/传感状态下稳定复现，也不能归因为手机不支持。需要继续做连续佩戴多轮、连接后等待及命令/停止回调对照。
