## 真机额外发现

iPhone 15 Plus / iOS 26.2 首次启动记录到 SQLCipher `file is not a database (code 26)`。

现场推断可能是数据库文件与当前 Keychain 密钥不匹配，也可能是数据库损坏或文件内容无效；本轮没有取出旧密钥验证，不能将其中任一项写成确定根因。

现已改为保守恢复：原数据库、WAL、SHM 和 journal 成套隔离保留，写入恢复标记，再创建新加密库。

任意重命名、标记写入或新库打开失败时，必须回滚原文件，不允许覆盖、删除或把旧数据误认领给新账号。

## 后续必跑清单

1. 修改 MethodChannel 方法时，同时执行 Dart 合同测试、iOS RunnerTests 和 Android 原生测试。
2. 修改测量逻辑时，同时验证成功、占位值、未佩戴、断线、超时、迟到回调和系统返回。
3. 修改网络参数时，必须断言 JSON 标量类型、值、路径、鉴权和失败文案。
4. iOS UI 测试的返回操作使用系统 pop route，不依赖英文 `Back` 或其他语言文案。
5. 每次真机验收都要记录机型、系统、设备路由、有效样本和日志；未产生有效样本不得写成通过。
