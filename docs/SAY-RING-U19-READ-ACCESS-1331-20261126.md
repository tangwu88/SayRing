# Say Ring 1331 U19 健康数据读取

2026-11-26，App 基线 `24a5433`。排查 iPhone XR 连接 U19M 后缺少血压等数据。

## 已定位的问题

- 从 Mac 请求 App 实际使用的中国站 `/global/api/saydian-app/v2/support/app-display?product=say-ring&platform=ios`，返回 HTTP 200，配置开放血压、心率和血氧。XR 对同一接口返回 `NSURLErrorDomain -1009`，系统网络路径显示 Wi-Fi 请求被拒绝。
- XR 的 1330 实际显示 U19M 已连接、有电量，点击同步后看到进度并结束，未提示上述指标因配置取不到而未读取。英文截图及真机日志已留存。这一轮没有血压回包和云端读回证据。
- 1330 点同步时不会主动补取 U19 读取配置。模拟重现确认无配置时活动仍成功保存，状态只报告已同步 1 条。同时，公共接口的 U19 配置刷新需要先等戒指原生配置完成，增加了首次进入手表时的等待。

## 修复

- U19 和戒指独立处理配置，可以共用同一次第一方 HTTP 请求。U19 未取得有效读取配置时，点「同步数据」会主动检查，最多等待网络配置 5 秒。取得配置后先确认当前表的实际能力，再读普通历史。到时仍无配置时继续读取活动和睡眠。
- 设备页及同步结果补充中英文读取状态。区分当前未取得配置与服务端明确未开放，已有的空历史及时间无法确认提示照常生效。
- 配置等待、能力确认和历史读写仍按原账号与设备连接范围校验。迟到响应不会替已断开的设备发出历史读取。配置持续不可用时只保留原有关闭状态，避免重复触发能力查询。
