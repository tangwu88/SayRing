# 2026-09-11 Android 扫描、能力展示与同步反馈修复

## 范围与成功标准

- 基线：国际版仓库 `main`，开工时 `HEAD == origin/main == bd7a69ee90eb9b20f16650e911d299effbb619f8`，ahead/behind 为 `0/0`。
- 真机：一台已授权的华为 Android 10 手机；覆盖安装保留登录、本机健康记录和手表绑定信息，不清数据、不恢复手表出厂设置。
- 目标：修复现场发现的扫描列表移动、同步没有结果提示、不支持通知项仍显示、真实提醒间隔可能导致页面崩溃、屏幕设置回写丢失能力边界以及闭源库扫描日志进入发行包的问题。
- 成功标准：定向与完整回归通过；Debug/QA Release 可构建；Release DEX 不再包含 Android 日志输出调用；真机可扫描、连接、同步、冷启动恢复，且只展示当前型号明确返回并已接入的功能。
- 安全边界：不改联系人、表盘、闹钟、通知开关、提醒、监测、屏幕参数、健康测量或账号；不执行支付、订单、OTA；设备标识、账号、原始日志、截图和构建产物不进 Git。

## 修改内容

| 范围 | 修改 | 用户结果 |
| --- | --- | --- |
| 扫描结果 | 同一设备的信号变化原位更新，新发现设备追加到末尾，不再按每次 RSSI 回调重排 | 列表不会在点击时突然换位，信号值仍实时更新 |
| 扫描提示 | 八语提示补充名称、信号判断及系统蓝牙/其他手机占用说明 | 用户可直接理解如何找设备，不显示实现术语 |
| 同步 | `syncDeviceData()` 返回真实成功/失败；按钮完成后显示本地化结果 | 不再用“按钮恢复”暗示同步成功 |
| 通知 | 只渲染 `supportedKeys` 明确返回的通知类型；缺少能力列表时不猜测展示 | 当前型号不支持的钉钉、企业微信等入口不再出现 |
| 健康提醒 | 接受手表真实返回的 15–240 分钟值，并补 15、180、240 分钟常用选项；异常值仅在编辑器内安全回落 60 | 15/180 等真实值打开编辑器不再触发下拉框断言 |
| 屏幕设置 | 回写映射保留最小/最大亮屏时长、抬腕支持和自定义时段支持字段 | 保存时不因 Flutter 往返丢失能力边界 |
| 发行日志 | R8 在优化发行包中移除 `Log.v/d/i/w/e/wtf/println`；增加规则测试和最终 DEX 审计 | 闭源扫描器不能把设备扫描原文写入 QA Release 日志 |
| 回归 | 新增扫描原位更新、屏幕能力往返、通知过滤、15/180 分钟提醒和同步结果提示测试 | 对应现场问题有自动化防复发覆盖 |

## SDK 依据与保守边界

- 按 [HBand SDK 官方 Android API 文档](https://github.com/HBandSDK/Android_Ble_SDK/wiki/VeepooSDK-Android-API-%E6%96%87%E6%A1%A3)继续使用新版功能包作为型号能力来源，并保持设备指令串行。
- 本地授权 SDK `vpprotocol-2.3.77.15.aar` 只提供单运动/多运动大类操作，未找到“当前型号逐项支持哪些运动模式”的权威读取接口。因此本轮没有按 W8/W9 名称补固定运动目录，也没有把宽泛多运动能力推断成跑步、骑行等逐项支持。
- 官方表盘等 `www.vphband.com` 请求是已区分的合作方服务，不属于第一方 API 回退；第一方仍只允许 `https://app.saydian.cn`。

## 真机结果

1. 扫描页连续样本中发现 6 个可连接候选；同一设备 RSSI 更新时相对顺序保持不变。测试按用户授权选择当时信号最强候选，未输出或记录名称、MAC。
2. 手表连接成功，未扩大联系人/通话权限。首次手动同步明确显示“数据同步完成”，连接全过程保持。
3. App 再次冷启动后自动恢复同一手表连接，无“连接失败”或重新扫描提示；恢复后第二次同步同样明确成功。
4. 消息通知页只读确认微信、短信存在，钉钉、企业微信和“当前手表不支持此项”不存在，也没有 SDK、BLE、协议等技术词。
5. 健康提醒页读取正常；久坐提醒编辑器显示开始、结束、间隔和原 60 分钟值，随后用返回键取消，未保存或改开关。
6. 屏幕显示页读取正常，亮屏时长存在；未更改任何屏幕设置。
7. 从冷启动前清空的临时日志窗口聚合：当前 App 进程 0 个 fatal、0 个崩溃进程记录、0 个 ANR、0 条 `E/flutter`；闭源扫描原文标记为 0。
8. 22 条结构化网络审计事件只出现 `app.saydian.cn` 和官方 `www.vphband.com`；旧赛电第一方域名事件为 0。该结果覆盖本轮实际路径，不替代系统级全流量长期抓包。
9. 测试结束时 App 进程存活、账号保持登录、手表保持已连接；没有留下无线 ADB、测试账号或手表设置副作用。
