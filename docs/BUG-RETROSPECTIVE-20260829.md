# 2026-08-29 跨端问题修复复盘

## 目的

本文件记录本轮问题的共同根因、正确修复边界和防复发规则。

后续修改必须先阅读本文件及 `REGRESSION-CHECKLIST.md`，不能只验证当前页面。

## 本轮结论

问题并非来自单一页面，而是集中在四类边界：设备能力、数据来源、厂商协议时序、调试/发布运行方式。

修复原则是以设备和服务端真实返回为准，不猜能力、不伪造数据、不把一种来源的数据当成另一种来源。

## 问题、根因与防复发约束

| 问题 | 根因 | 本轮处理 | 防复发约束 |
| --- | --- | --- | --- |
| iOS 设备地址显示为乱码或 UUID | CoreBluetooth UUID 被误当成 MAC 展示 | 连接仍使用 UUID；只有 SDK 返回且通过格式校验的地址才显示为 MAC | UUID 永远标为“iOS 连接标识”，不得截取或改写成伪 MAC |
| iOS 在线表盘提示参数无效 | 在线表盘文件被错误路由到本地表盘 `switch`，并把市场槽位和已安装表盘混为一谈 | 新增独立网络表盘传输，校验文件长度、协议、表盘形状，写入后读取设备状态确认 | `switch` 只切已安装 `imageId`；`upload_network` 只传在线文件；能力资料不完整时不显示商城 |
| iOS 心电波形异常 | SDK ADC 原始值被直接当成可绘制波形，历史和实时来源也未区分 | 使用 SDK 换算为 mV；只有校准成功且信号可用时标为 `rawVersion=2` | 不绘制原始 ADC；无可用波形时只保留心率、HRV、QT 等客观字段 |
| 关爱邀请角标和列表不一致 | 角标统计了已同意、已拒绝等全部关系 | 角标和待处理页统一从 `pendingCareInvitations` 派生 | 同一业务状态只能有一个派生数据源，不在页面分别计算 |
| 远程关爱心电和其他指标不准确 | 聚合接口、原始日记录和远程成员数据混用，失败或零占位被当成真实值 | 补齐心电接口和独立展示；标记 `remote_member`；失败、空数据、未授权分别展示 | 远程数据不得写成自己的手表数据；接口失败不得回退成健康值 0 |
| Android 血压及高级历史缺失 | 只读取 `OriginData/OriginData3`，漏掉半小时血压/心率和设备手动测量历史 | 串行增加半小时数据、手动测量历史、心电历史读取并统一去重 | HBand 耗时命令必须串行；新增指标时同时检查实时、Origin、手动历史三条通道 |
| Android 重复或字段不完整 | 相同秒记录按“先到先得”去重，可能保留字段较少的一条 | 合并同秒记录并优先保留字段和波形更完整的记录 | 去重必须是信息合并，不得简单丢弃后到记录 |
| 运动入口与设备能力不一致 | 页面曾被整体隐藏；另一处又按型号猜测能力 | 恢复入口，但只展示设备和原生桥接共同确认的运动模式 | 未连接、能力未完成握手或桥接未实现时必须隐藏；不得用默认四项兜底 |
| 健康预警遗漏或重复 | 只处理实时测量，历史同步没有进入预警链路；重复同步会重复生成 | 最近手表历史进入统一评估，并按记录 ID 去重保存来源 | 只处理设备/服务端明确数据；不从普通数值推断疾病；旧记录不补发实时预警 |
| iOS 从桌面启动“闪退” | Debug FlutterEngine 脱离 Flutter/Xcode 后不能独立运行 | 调试使用附加状态的 Debug；独立冷启动使用 Profile/Ad Hoc/TestFlight/Release | 不能用脱离工具的 Debug 包判断发布版稳定性 |
| Xcode 偶发 `.pcm`/`.scan` 缺失 | 两个会话同时构建同一仓库，共用 DerivedData，彼此清理临时文件 | 等待另一构建结束后再重试，不删除源码或设备数据 | 同一仓库的 iOS 构建必须互斥；开始前检查 `flutter run` 和 `xcodebuild` 进程 |

## 本轮发现的交叉回归风险

1. 清洗心电数据的执行顺序会影响来源判断。实时 App 测量必须先标记为 `app_measurement`，再执行质量校验。

2. 云同步完成后可能遇到页面已销毁。异步回调必须先检查控制器是否已释放，再通知 UI。

3. “为了让入口可见”而补默认能力，会造成入口可点但设备永远无响应。能力必须来自“设备支持 + 桥接实现”。

4. 同一指标可能来自自己的手表历史、App 手动测量和远程成员。展示、预警、上传和去重都必须保留来源。

## 固定数据契约

- `watch_history`：手表历史同步，只允许以设备原始时间入库。
- `app_measurement`：用户在 App 内发起的测量，可触发当前会话的交互反馈。
- `remote_member`：远程关爱成员数据，只用于成员详情，不混入自己的趋势与预警。
- `manual_entry/imported/unknown`：必须保持原来源，不得自动升级为设备真实测量。

心电 `rawVersion=2` 只表示已换算、可解释的真实 mV 波形；它不是诊断结论。

- `flutter analyze --no-pub`：零问题。
- `flutter test --no-pub`：232 项全部通过。
- Android Debug/Release：均构建成功。
- iOS Debug/Profile 无签名构建：均构建成功。
- iOS RunnerTests：`build-for-testing` 成功；直接 XCTest 运行受 Debug FlutterEngine 测试宿主限制。
- Android 真机：阶段性 Debug 包成功启动并恢复 W9S 连接，未发现 `FATAL EXCEPTION`；最终包待 USB 恢复后复装。
- iPhone 15 Pro Max：Debug 在 Flutter 附加状态下安装、启动并持续运行，关爱成员接口返回正常。
- iPhone 15 Pro Max：签名 Profile 脱离工具连续冷启动 3 次，进程均持续存活。
- iPhone 12 / iOS 16.3：Profile 安装、启动、W9 配对和能力握手完成；独立长期存活因旧系统查询限制未确认。

真实在线表盘传输、有效心电电极波形和非零运动记录，必须以最终现场结果更新实施日志，未完成前不得写“真机通过”。

## 后续修改的停线条件

以下任一情况发生时，不得提交为“完成”：

- 远端基线未确认，或本地存在来源不明的覆盖修改。
- 某个入口依赖的设备能力或原生桥接没有同时确认。
- 只跑定向测试，没有跑全量测试和双端构建。
- 只验证 Debug 附加启动，没有验证 iOS Profile/发布形态独立启动。
- 真机没有产生有效样本，却用模拟值或旧截图代替结论。
