# iPhone XR 上的 R8 连接实测

2026-11-05。在 iOS 18.7.10 的 iPhone XR 上运行 Say Ring 1.0.11（1254）普通调试版，客户端代码基线为 `cd5d2bb`。目标为 `SD_RING_R8`。开始时 XR 连着 R7 Ultra。

## 操作与数据保护

- 用 `xcrun devicectl device info apps` 核对包和构建号，用 `device copy from` 私下备份现有应用容器。通过 Flutter 调试调用设备页使用的扫描、设备选择和连接方法。运行前后核对当前账号、正式应用入口和绑定对象。
- 暂时断开 R7 Ultra，保留原绑定。以实际扫描发现的唯一 R8 标识查询第一方绑定历史，已有绑定得到确认后才尝试连接。系统恢复列表试验使用同一标识。全程没有解绑、重置、清空指令或戒指设置写入。
- 最初的调试会话中断。用同一普通构建原位接回调试，修正本机观察脚本对异步完成状态和过期对象引用的处理。以下次数取自 XR 原生连接日志中本轮新增的请求，排除了调试器重试和历史日志。

## 五次连接请求

| 入口 | 实际结果 |
| --- | --- |
| 搜索列表，4 次 | 2 次等待约 35 秒后结束，期间未收到系统蓝牙连通回调。另外 2 次先连通，在设备功能确认前断开。系统报连接超时，错误码 6。 |
| 系统恢复列表，1 次 | 该列表能返回同一枚 R8。直接选中后约 6.8 秒收到系统蓝牙连通回调，约 0.7 秒后断开，系统同样报连接超时。 |

三次短暂连通均未收到设备 SDK 注册完成的回调。实测定位到蓝牙连通至设备功能就绪之间，尚无证据区分射频条件、戒指状态或适配端的具体成因。没有启动 R8 的历史读取，活动同步、睡眠同步和就绪后的自动重连都留待复测。

用户选择先保存结果，未执行充电座唤醒对照。结束时通过保存的原绑定恢复 R7 Ultra，并确认设备功能就绪。同一账号原有的 92 条健康记录按标识逐条核对均在。原始标识、日志、账号数据和备份仅留在本机。本轮只记录真机测试，未改产品代码。
