# Say Ring 1.0.11（1256）：XR 双戒指、界面与文案

2026-11-05 晚至 11-06 凌晨。基于 Say Ring 的 `codex/integrate-latest-20261031`，起点 `c0524ba`。先测 XR 原先保存的 R7 Ultra，再选择实际扫描到的 R21。两个型号、不同轮次的结果分开记录。此版本仅供本地测试，不替换已送审的 1255。

## 用户能看到的变化

| 原问题 | 现在的表现 |
| --- | --- |
| XR 的 R7 Ultra 有已保存的真实活动，但首页连入口也没有 | 识别到原先保存的本人、同一枚戒指的真实步数时，可在首页进入只读活动记录。没有数据不补零，也不增加实时测量能力。换戒指或账号后，已经打开的旧记录页失效。 |
| 设备页主要操作旁有解绑；遇到同步未完成时描述内部应答 | 读到电量后只保留同步，解绑在连接详情内。完整、部分更新、明确无新数据分开；只有真正保存了记录，才显示更新数量。 |
| 问答、启动、演示、手势及固件页有开场白或开发术语 | 移除助手自我介绍、首页口号、演示审核说明、固件后台配置和模式“上报”等文字。问答保留回答来源；演示明示是示例；固件未连接时只说连接后能查看什么。 |
| 问题发送失败，会附带供应商代码，还可能在返回首页后重复弹出 | 失败只标在那条未发送的问题下。登录过期提示重登，手机网络故障提示检查网络，服务一时繁忙提示稍后重试。旧响应不能清掉刚发生的其他错误。 |
| 睡眠报告会展示远端提供的任务说明；错误有时是内部原文 | 只根据确认的状态提示生成、刷新或重试，不显示任意远端进度文字。提交前仍说明第三方 AI 会处理哪些睡眠汇总，须本人同意；已有健康记录和协议版本不变。 |
| 睡眠、运动、单位和设置有重复说明 | 睡眠按所选日区分无记录、仅总时长和有分段；详情说明可展开。地图不可用时仍显示已有定位点组成的轨迹。单位设置按距离、温度分组，选中即生效。 |
| 运动页根据旧提示中有没有“未确认”来决定是否提示重试 | 根据实际的同步结果显示是否要重试。当天没有记录时，不在既有空状态下再重复说明一遍。 |
| 大字时按钮、价格、输入栏、日期容易挤在一起 | 登录、注册、结算、物流、健康资料等在空间不够时分行；运动计时不拆成两行；帮助和同意面板可滚动到页尾。 |
| 个别页面会误用另一项操作的错误，或在切换账号后显示旧结果 | 地址、物流与关爱读取不再套用无关的戒指错误；迟到的旧账号请求丢弃。趋势按本地日历日换日、周、月；周期近期窗口跨夏令时不多出或漏掉一天。 |

## XR 实测

- **R7 Ultra，原安装 1255：**普通 App 冷启动复连约 7 秒，电量 18%，连接正常后无“重新连接”。两次手动同步均约 26 秒退回可操作，均未收到完整结果。该戒指已有两条活动记录，最近 31 日未查到睡眠记录；无依据判定为“同步成功”或睡眠漏记。本次修复的是已保存活动在首页消失，未更改戒指历史协议。后续要用同一枚戒指在有已知新增活动/夜间佩戴样本时对照完整回包。
- **R21，实际扫描后切换：**蓝牙搜索同时看到 R8 和 R21，选 R21；核对既有绑定历史，没有触发首次绑定清空。一次手动同步 15.44 秒，获得 78 条（心率 26、皮温 26、血氧 12、HRV 14）。该戒指最近七天返回无睡眠记录，近 31 日没有步数行；这不能代替真实佩戴睡眠准确性或步数增量测试。
- **普通 1256：**通过独立的 XCUI 进程操作常规 App，确认 R21 能读到真实电量、正常状态隐藏“重新连接”、展开/收起连接详情不触发解绑、手动同步实际完成；真机打开健康、睡眠说明及单位页。中途出现的 iOS 配对框挡住页面，不能把页面无响应算成已连接；匹配到同一枚 R21 后完成配对，重新核对电量和数据。手势/监测入口在只读巡检中另有记录，不代表本轮完成物理手势或测量。
- **数据：**每次安装前私下备份并校验应用容器，原位覆盖，未卸载、未登出、未重置或改戒指设置。安装后启动前独立核对 Documents、Application Support 和业务偏好文件。比对本轮开始的 104 个原始健康记录 ID，104 个全在；上次会话的 92 个也全部仍在。新增/重复读回的记录与这个基数分开计算。
- 本次没有人为断开蓝牙后测试锁屏远距离自动恢复，也没有对新鲜睡眠、急救呼叫、实际支付、短信发送或线上生产配置进行操作。未在华为安装本轮版本。

## 回归与复查方式

- 产品入口：健康/睡眠/指标趋势、活动运动与轨迹、设备连接与能力设置、健康提醒与生理周期、健康问答和百科、登录/账号/设置/隐私/关爱、商城/地址/订单/物流等。106 个页面或可区分状态，常规字号 390 宽及 2 倍字号 320 宽分别渲染，共 212 张；未满足条件的功能按真实状态展示。模拟数据不作为真机或远端服务结果。
- 截图入口：`flutter test --no-pub --dart-define=IOS_REFERENCE_WIDTH=390 --dart-define=IOS_REFERENCE_TEXT_SCALE=1 --dart-define=IOS_REFERENCE_OUTPUT=<私有输出目录> test/support/ios_inner_page_capture.dart`；第二轮宽 320、字号 2。通过真实页面的结构和渲染检查缩放、操作区和错误/空状态；报告链接仅选用合成图片。
- 静态与逻辑：`flutter analyze --no-pub`；分别在 `TZ=Asia/Shanghai`、`TZ=America/Los_Angeles`、`TZ=UTC` 执行 `flutter test --no-pub --reporter expanded --concurrency 6`。重点包括受限型号只读记录、切换账号、日历边界、服务进度文本过滤、生成授权、地图回退以及大字输入。
- 双端构建：iOS 用普通 `lib/main.dart`、显式版本 1.0.11/1256，分别配置 Debug/Profile，串行 `xcodebuild` 并严格校验签名、包名和授权设备。XR 使用可独立启动的 Profile。Android 使用原发行配置生成 Debug/Release，双 ARM，执行 `:app:testDebugUnitTest`。发布脚本以隔离夹具执行 `python3 -m unittest discover -s scripts/release -p 'test_*.py'`（35 项），不操作真实下载页。
- 过程中修正：初版日期验证发现美国时区夏令时边界；大字体下输入/操作拥挤、活动时间断行和连接详情定位不稳定；一期回归仍匹配旧相机及保存/生成提示，按实际行为更新，未取消对应动作/授权断言。再次发现“仅有总时长”在可刷新状态与不可刷新状态不一致，保留两种操作区别、统一真实含义后再跑全量。
- 问答错误通过模拟服务失败验证：分别注入上游鉴权、限流、超时、手机断网和凭证过期；检查当前消息、返回后的全局提示及迟到错误隔离。未向真实提供商发送个人健康内容。构建期间若源码又发生变化，丢弃该次产物；以下最终验证均以同一份冻结代码为准。
