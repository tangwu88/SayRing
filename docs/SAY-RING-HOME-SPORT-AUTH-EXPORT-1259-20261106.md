## 复现与原因

- 用实际控制器和存储替身复现：旧缓存读取在新记录写入、刷新之后才结束，会以旧快照覆盖新的首页缓存。测试先失败，再增加读取版本护栏后通过。这证明的是缓存竞态，不代表实物已经传回全部新记录。
- “同一活动 ID 导致新步数被忽略”的最初假设已撤回：检查实际 AAR 映射器后，ID 已含时间、指标和值，不应据此修改数据库冲突策略、重写 ID 或覆盖历史。
- 运动首页原来在 `initState` 自动发起 BLE 历史读取；连接后独立的运动历史读取也可能仍占用原生窗口，而界面仅看到健康同步状态。原生开始运动的互斥护栏正确，不能绕过。
- 路由重建 `WearableSyncResult` 时漏传 `protocolChecks`。必须保留未知 HRV 协议状态，不能将已协商范围结束写成所有历史完整。
- 登录、注册和微信绑定验证码字段没有六位输入限制，平台重复自动填充可留下十二位。
- 周期导出直接写 `kind` 和 `jsonEncode(data)`，因此客户看到 `period/daily/fatigue/strong`。只变更导出展示，不改存储或云端格式。
- 设备查找入口原先只要系统缓存列表非空就不扫描；缓存设备可能不在附近，列表也不会刷新。
