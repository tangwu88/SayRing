## 已发现问题

### P1 活动距离米数被当作公里显示

- 复现：ET488 同步后打开健康首页。
- 预期：1892 步对应距离以公里换算后显示。
- 实际：页面显示“距离 1582km”。
- 根因：鸿蒙 Vep 日常健康回调中的距离原值未做米到公里的安全归一化，直接标记为 `km`。
- 影响：健康首页、活动趋势、记录详情及英里换算皆会放大 1000 倍。
- 计划修复文件：`WearableContracts.ts`、`VepWearableService.ets`、`Index.ets` 及相关测试。
- 预期：新同步和旧缓存记录都使用统一公里值；运动列表同样遵循用户选择的公里/英里。

## 已完成修复

### 活动和运动距离统一为公里

- 日常活动按步数辅助识别厂商返回的是米还是已换算公里，避免重复除以 1000。
- 运动历史的 `allDistance` 按厂商协议从米换算为公里。
- 首次加载旧记录时修复曾以 `km` 标签保存的米值，修复过程幂等并回写加密数据库。
- W9S 本轮没有返回非零活动/运动记录，因此只完成自动测试、编译和旧记录迁移验证；按用户要求不再切换 ET488，未用另一台表补做现场数值核对。

### W9S 血氧测量无法结束

- 复现：启动血氧后厂商持续回帧；停止命令已经写入 BLE，但 Promise 不返回，页面持续显示“结束测量”。
- 根因：官方鸿蒙 SDK 将血氧定义为一次性读取，现有实现却按持续测量处理；同时所有停止接口都没有超时边界。
- 修复：血氧成功结束但没有有效值时立即释放命令队列；全部手动停止最多等待 3.5 秒；停止中防重复点击；停止后迟到的启动异常不再覆盖完成状态。
- 真机结果：W9S 血氧启动后恢复为“手动测量”，无有效值时显示真实空结果，不保存伪数据，连接保持。

### 结束测量丢失最后有效读数

- 复现：W9S 体温过程中显示 `35.6°C / 29.7°C`，结束时厂商末帧为空，页面误报“未收到有效读数”。
- 根因：停止回调可在 Promise 返回前覆盖当前测量值，旧实现虽然截取过值，保存时仍读取了已被清空的当前状态。
- 修复：测量期间独立保存最后一组有效值；结束时优先保留当前有效值，否则使用最后有效值，再写入本机加密记录。
- 真机结果：重新测得 `35.6°C / 29.4°C`，结束后值和记录均保留，按钮恢复为“手动测量”。
