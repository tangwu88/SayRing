## 原因及修改

- `refreshSportRecords` 在自动重连健康同步后、运动结束及记录页打开时读取运动历史。原实现将 `COOLWEAR_SYNC_TIMEOUT` 及读取失败写到通用 `errorMessage`，因此后台结束也能打断其它页面。
- 控制器新增按账号代次和当前目标绑定的运动历史状态：读取中、完成、部分保存、未完成、失败。仅运动记录页读取此状态；不写入/清除全局错误，不吞掉其它操作错误。断连/账号切换清理归属，旧目标迟到结果不改新目标状态。
- 保留 SDK 读取、互斥和入库逻辑。已收到的有效运动继续保存并展示；部分/超时不标记完成；正常返回空列表清理旧失败状态；本地存储读取失败不清空已显示记录。没有通过将沉默改成空历史来消除提示。
- 运动记录页在本页展示简短状态与重试入口，已有列表仍可打开；离开该页后不弹迟到运动提示。空本地列表和本次读取未完成分别呈现，不以“暂无记录”替代失败。九份既有语言目录补齐三条文案及生成文件。
- 原生 SDK 路径只读核对：sportOnly 使用类型10计数；已请求 DATA 的明确空回复/合法空终包可完成，命令ACK和沉默不能。原生完成判断和30/90秒窗口保持不变；本轮是反馈归属修复，不声称厂商未返回的历史已补齐。

涉及 `lib/services/app_controller.dart`、`lib/ui/pages/sports.dart`、`lib/l10n` 目录与生成文件；对应累计运动修订/用户流程测试更新，并新增 `test/sport_history_feedback_test.dart`。
