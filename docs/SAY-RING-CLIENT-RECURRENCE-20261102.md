# 客户端反复故障复查与修复

2026-11-02，起点为已与远端核对的 `360e6e6`。复查从之前的两份审查记录和 XR 的真实发现故障出发，沿 Flutter、iOS、Android 的生产调用路径检查账号、设备和回调交错。下列失败在受控环境复现；未将某个代码问题推断为过去每次现场故障的原因。

| 触发场景 | 此前的实际行为 | 修改与回归判据 |
| --- | --- | --- |
| 搜索、退出、再搜索或切号交错 | 旧恢复列表能覆盖新搜索，迟到的失败能留下错误的权限提示；已退役搜索的收尾还能删除用户刚看到的候选。原账号已准备或正在读取的手动候选也可能在换号后仍可用 | 搜索和恢复共用轮次；手动选择同时校验账号、连接和搜索轮次。清理在本轮开始执行。分别回放旧结果成功、报错、取消后点击新候选、A → B → A 切号 |
| 会员明确连接，手机暂时读不出绑定记录 | 无法确认绑定时仍可能走普通绑定上报、读取历史，影响下一次首绑判定 | 受管型号此时停止并支持重试。恢复读取后，有历史的会员保留原绑定路径，真正首次绑定的会员仍由服务器判定；不根据本机读取异常清空戒指 |
| 连接认证期间收到“历史已就绪” | 同步过早占用连接使用的代次，能力回包回来后连接仍卡在认证状态 | 在连接和认证阶段忽略提前触发的同步请求，由连接就绪后的既有策略启动。检查能力能到达就绪态 |
| 一批历史混有多枚戒指的记录 | 同一通道的其他设备或缺少标识的记录可能被当作本次历史保存 | 完整和部分回包均逐条核对设备及嵌套睡眠记录，混合批次只保留匹配的数据，不提前推进已读日期。已有数据库记录不做批量改写 |
| iOS 系统名未到，或名称和地址分两次广播 | 仅依靠系统名可能漏掉可选戒指；恢复路径可能忽略相互矛盾的名称 | 在同一外设标识上合并有效广播信息；服务归属冲突即拒绝。覆盖后续包补地址、停止扫描后的迟到包、精确 UUID 仍须符合通道路由 |
| iOS 同一次连接重复注册或回调乱序 | 重复注册可以重新进入握手，成功后的迟到失败能拆掉已就绪连接 | 注册与握手结果均只采纳一次；取消操作核对外设对象和本轮连接。用先成功后失败、其他外设迟到的回调复测 |
| Android 单条指令无应答，或上一枚设备的服务就绪 / 读取广播迟到 | 厂商旧回调把无应答与真实掉线混合，可能清掉健康连接；丢掉地址会让另一设备的广播参与本次握手 | 按原始广播类型、实际设备地址与读取结果处理；保留真实断连后的恢复。用项目随附 SDK 的广播行为及生产方法做对照 |
| Android 振动款相机退出后重新进入 | 退役页面排队的戒指手势可能触发新预览的快门 | 快门限定在同一相机页面、同次连接和同一戒指，关闭后旧监听作废。检查正常拍照指令仍能送出、旧事件不能送出 |

规范落在对应代码的中文注释及[客户端防复发清单](CLIENT-REVIEW-CHECKLIST.md)。回归用例分别位于设备扫描、精确恢复、账号设备、连接上报的 Flutter 测试，以及两端的原生回调夹具。原有五项审查覆盖的退出凭证、授权期限、蓝牙状态重置、更新检查和加密存储保护继续由既有用例验证。没有更换 SDK 或发布生产配置。

## 本轮验证与真机边界

- 在旧实现上重放旧扫描结果、认证期间的就绪通知、混合设备历史及绑定读取失败，可观察到错误状态或写入。安卓单指令无应答、旧快门以及 iOS 握手乱序均用原生调用验证；修复后分别检查合法事件仍能生效、过期事件不改变新会话。
- Flutter 全量测试在上海和 UTC 时区分别通过 1,803 项；静态分析无问题，298 个 Dart 文件通过格式检查。Android 单元测试 82 项通过，两个平台配置的原生回归在本机通过（Android 6 项、iOS 53 项）。工具集 165 项通过，1 项仅适用 Windows 的权限测试在 macOS 跳过；鸿蒙契约 547 项及发布工具 35 项通过。各组可能覆盖相同场景，不累加计算。
- Android Debug 与 QA Release 构建成功。iOS 普通入口的 Debug 和 Profile 均已构建并验证开发签名。上述构建均为本地验证产物。
- 现场查看时，XR 上原安装版本已连接 R8，同步和设备功能入口可见。本轮保留现场连接和原有数据，未覆盖安装；这不证明新改动已在真实断连、长时间后台或实际快门动作下通过。下次真机验收应分别记录这些结果，不以构建或模拟回包代替。
