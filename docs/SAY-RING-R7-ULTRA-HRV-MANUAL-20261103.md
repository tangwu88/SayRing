## 已确认的问题与证据边界

1. **启动拒绝没有结束测量窗口。** 首次绑定尚未结束、设备未连接、当前版本或设备无手动能力等早退分支只更新全局 `errorMessage`；窗口只读 `measurementErrorMessage`，并忽略 `startMeasurement` 的 false 返回值。此时未创建测量计时器，确实可无限等待。
2. **计时器创建过晚。** 原实现等待原生启动完成后才创建 HRV 180 秒上限。启动本身挂起时，整个流程没有该上限保护。
3. **旧异步操作可能覆盖新测量。** 取消后重试同一指标，旧启动结果、旧启动失败或旧停止收尾缺少独立测量轮次校验。不能仅靠相同连接代次和相同指标判断仍是同一轮。
4. **Android 原厂实时与历史回包共用回调。** 固定版本 AAR 的 type 60 和 61 都使用 `RCVD_DATA_TYPE_RRI_HRV`。必须在原厂公开处理器 API 上区分实时与历史，不能让迟到历史结束当前手动测量。
5. **iOS 结果可能先于启动确认发布。** 提取真实生产方法的宿主测试复现：有效 type 60 在启动 ACK 前到达时立即发布，随后正常停止可能撞上“启动未确认”取消流程。现在只在本轮内存暂存，ACK 成功后退出原厂回调，再复核连接和测量轮次后发布；失败、停止、超时、断连均丢弃。

上述控制流问题已有宿主失败回归证据；不等于已证明这枚 R7 Ultra 不返回 HRV。设备是否返回 type 60、是否存在质量或时效拒收，需要本轮真机诊断。
