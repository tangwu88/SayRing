## 2. 本轮发现并修复的问题

### 显式断开后无法重新扫描 ET488

复现步骤：连接 ET488，调用 App 断开，再立即扫描。Flutter 已显示断开，但三轮扫描均找不到刚断开的 ET488。

根因：Veepoo SDK 的 `automaticConnection` 仍在后台工作。它会在 Flutter 清理连接状态后重新占用 GATT，会话，导致手表不再广播；界面状态与原生 SDK 状态因此分叉。

修复：

- 显式断开前关闭 SDK 自动重连。
- 等待原生断开回调后再完成 Flutter 调用，并增加 3 秒兜底超时。
- 使用连接代次门禁拒绝重入和迟到回调。
- 用户主动扫描时取得连接选择权，先停止旧扫描并释放隐藏 GATT 会话，再延迟 0.75 秒开始 12 秒扫描。
- 扫描中收到旧断开回调时只清理会话，不触发后台恢复。
- 用户明确选择设备连接后才重新启用自动连接。
- 增加原生单元测试，覆盖重复断开、错误代次、迟到完成和重置。

复测结果：断开、首次重扫、连接、认证及恢复 `ready` 全部成功。
