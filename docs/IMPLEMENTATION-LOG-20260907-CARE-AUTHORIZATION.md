# 三端关爱授权撤销状态核查

## 现场事实与范围

- 主线程在鸿蒙共享设置临时关闭一项心率授权，保存并重新打开确认仍为关闭；iPhone 接收方重新进入成员页仍显示“对方当日没有可共享的该项记录”。主线程随后恢复原授权。
- 本次没有取得该次读取的原始响应，不能认定现网返回了 403，也不能推断服务端泄露数据。子任务没有操作手机、账号、共享开关或服务器。
- 修改前安全更新远端，当前开发分支与上游无分叉；保留全部并行改动。

## 已证实客户端问题

- Flutter `api_client.dart` 的单项健康查询异常分支先尝试总表回退，再判断 403。因此“总表 200 空 + 单项 403”被改写为无记录；“总表含旧心率 + 单项 403”可重新显示旧心率。
- 两种组合分别覆盖 HTTP 403、HTTP 200/业务 code 403。直接运行生产 API 的测试在原代码上 4 项失败；授权空态 UI 反例另 1 项失败，401/超时/离线 3 项通过。日志 `/tmp/saydian-care-authorization-before.log`。
- Harmony `AccountClient.careMetric/careMetrics` 已优先处理 403 为 `unauthorized`，不使用总表绕过。现有生产 API 测试两项重新执行通过；本次未改 Harmony。

## 修复

- Flutter 单项 403 是权威拒绝，优先于任何总表回退；返回独立 `unauthorized` 状态、空 records，不保留 latest/min/max/avg。
- 概览卡片和单项详情显示锁图标与“对方未授权此项目”；即使传入数据混有旧 records/摘要，未授权状态也不显示它们。
- 保留其他已授权指标与现有 404/服务错误兼容逻辑，401、网络超时和离线仍为失败，不回退为旧数据。
- 删除原分支中已不可达的 403 文案条件；没有增加依赖或修改其他 UI。

## 追加：统一响应码拒绝边界

- 主线程确认扩展处理字符串 `"401"/"403"`：统一响应码解析只接受整数值或完全由 ASCII 数字组成的字符串。不截取部分数字、不接受字符串小数、空白/空字符串或未知格式；未知业务码不当成功。
- HTTP 非成功状态先于响应体业务码；HTTP 403 加正文 `"401"` 不触发登录刷新，HTTP 200 加合法 `"401"` 才走原单次刷新语义。通知可选端点也复用同一解析，删除重复转换逻辑。
- 原先只数字状态的版本完整 UTC/Shanghai 各 448 项通过；首轮静态检查指出新增测试 3 条无花括号提示，清理后零问题。以上仅为中间版本，最终字符串状态版结果见下方。
- 新最终定向测试 66 项通过，含 16 项授权/响应码/UI 测试。覆盖数值与字符串 403 × HTTP 200/403 × 总表空/旧值、字符串 200 成功、401/超时/离线不回退、未知业务码与非法格式拒绝、HTTP 状态优先以及单次刷新。
