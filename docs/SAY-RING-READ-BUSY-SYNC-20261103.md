# XR 相机恢复和华为历史同步复查

2026-11-03。基线为 `6da9b3f`，测试使用原账号、原绑定和普通 App 入口。iPhone XR 配 R8，华为 PPA-LX3 配另一枚 R7 Ultra。只比较同一设备、同次操作口径一致的读数。照片、健康数据、账号和设备标识留在本机。

## 复现与修改

- XR 上次从系统相册授权页返回，手机预览已恢复，但戒指遥控一直提示设备忙，手动重新打开后才就绪。本轮先在原包主动同步中打开相机，预览约 1.5 秒出现，遥控约 9.9 秒自行就绪。这说明普通同步和首次系统授权返回的表现有差别。用原生和 Flutter 回归分别复现了读取占用、读取结束后仍未再次尝试的路径。
- iOS 仅在原生能确认读取正在占用设备、开启相机遥控指令尚未发出时，通知页面限次重试。最多五次，等待间隔合计 11.5 秒。在原预览上继续使用手机快门；离开页面、切后台、换设备或启用新预览时，旧回调不得接管。对已经发送但回执不明确的写指令继续保留原有保护。
- 华为原包多次回传相同步数、距离、热量时，每一批都会重新开始静默计时。一次实测在约 2、5、12 秒收到相同记录，约 42 秒返回部分同步；本轮原包约 2.1 秒读到活动，约 34.6 秒返回部分同步。固件没有给出整批传完的确认。
- Android 逐条比较有效记录标识和内容，重复批次不会刷新健康读取的进度。同一标识内容确实改变仍延长等待。运动记录有独立读取者，保留原有接收窗口以及已接收的运动记录。健康读取已经返回时，晚到的有效健康记录仍可经原有回调入库。静默期限仍是 30 秒，整轮上限仍是 90 秒。
- 另在运动页复现了跨两次读取时旧值总是优先的问题。相同模拟记录由 120 秒、90 步增长至 130 秒、96 步，原版在完整和部分返回时都保留旧值。Android 现在核对当前账号、戒指、运动类型、起点和厂商记录标识，在同一数据库事务内比较时长、步数、距离、热量。仅当四项都明确、没有一项回退且至少一项增长时才更新累计量。仅到达顺序无法区分旧包和修订，数值有冲突时保留既有数据。库内的路线、心率采样及未知字段原样保留。
- 检查华为原绑定时发现，Android 以前只查询系统已配对设备。戒指可能已建立低功耗蓝牙连接，却没有系统配对记录。R7 Ultra 所用通道现在在手动与自动恢复时先核对当前账号原有的精确设备地址、设备名称和系统连接或配对状态。真正连接前再次查证，并走正常握手。目标过期、查询超时或旧接口不可用时继续搜索。系统级连接用于寻找候选，实际就绪仍由 App 的设备信息握手确认。[Android 的系统连接状态说明](https://developer.android.com/reference/android/bluetooth/BluetoothManager#getConnectedDevices(int))
- Android 历史绑定可能使用小写地址，而系统返回大写地址。厂商按原始字符串计算运动记录标识，两种写法会产生不同的标识。仅对已核对的同一枚戒指、同一运动与起点接收相应标识，并优先修订原有行。跨账号或不同戒指的相似记录继续隔离。

## 回归方法

- 运行 `flutter test --no-pub test/ring_camera_lifecycle_test.dart`，覆盖自动恢复、上限及人工重试、旧回执、新预览、换设备与后台。原生用 `node --test tool/qring_photo_session.test.mjs` 编译生产 Objective-C 方法并执行，另核对普通命令入口的分流顺序。旧代码无法区分可重试的只读占用，新版由这些用例防止回退。
- 运行 `node --test tool/test_coolwear_android_sync.mjs`，抽取实际 Java 方法并用单调时钟重放 2.2、5、12.2 秒的重复包。旧代码在 32.2 秒仍等待，新版在该时刻返回已收到的记录。另投递同标识的数值变化、晚到的运动、后来加入的运动读取、无有效标识的数据及持续到 90 秒的流量。两项原生专项均加入相应平台的持续集成。
- 运行 `flutter test --no-pub test/coolwear_android_sport_revision_test.dart`，核对完整和部分读取、跨账号、错误戒指、重复和倒序回包，以及运动页与数据库中的记录。SQLite 用例保留本地路线、心率和既有未知字段。这组累计量由测试生成，未把它算作实物新增步数。

## 本轮真机

- **XR 与 R8**。1.0.10（1226）调试修复版已原位安装，覆盖前后 56 个既有数据文件的内容一致。普通设备页手动同步后立即进入相机，约 1.49 秒观察到预览，约 9.66 秒遥控就绪，同时同步返回成功。另一次读取设备详情时进入相机，约 1.39 秒观察到预览和遥控就绪。两轮均未手动点重试，返回设备页后原账号和 R8 仍就绪。两轮没有直接观测到仅因读操作被拒绝的标记；该分支由原生和 Flutter 定向用例验证。上轮已由使用者确认 R8 手势确实拍到照片。本轮沿用已授予的相机权限。
- **华为与 R7 Ultra**。以原签名、同包名 1.0.10（1228）覆盖安装同步修复版，系统保留原安装身份和首次安装时间。运行时回读的账号和记忆戒指匹配。覆盖后观察到两次系统蓝牙建立连接，服务发现及通知订阅开始，但分别在发现服务后约 0.94 秒、0.18 秒关闭，尚未完成 App 的戒指信息握手。只读采样显示系统未配对该戒指，普通 App 尚无已确认的原生连接目标。早先的关闭没有取得调用栈，在之后的监看窗口也没有再次观察到相同的关闭。单凭这些事件不能确定谁发起了那两次关闭。
- **XR 最终共享代码复测**。在已原位安装的新原生桥上热重启一次，运行时验证已加载新增的恢复接口。原账号、R8 绑定均一致。自动同步完成后，从普通设备页再次同步，6.23 秒返回成功，界面报告同步 49 条。没有把界面计数当作本次新增。最终仍为原戒指已就绪、同步空闲、前台设备页可用。
- **华为既有记录核对**。在戒指尚未恢复时，页面缓存仅呈现原目标 16 条。从同账号的本地数据库逐条比对，原目标 22 条记录的标识集合与覆盖前完全一致，其中有 6 条活动记录。已有记录的可读性与本次固件能否回传新记录是两项不同的验收。
