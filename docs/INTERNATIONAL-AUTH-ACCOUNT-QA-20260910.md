## Invocation and private record

The parent must first create a dedicated directory outside this repository and restrict it. Windows requires a protected DACL whose allow entries name only the executing operator, SYSTEM or Administrators; the tool reads ACLs but never changes them. POSIX requires current-user ownership and no group/other access. The directory must not be the repository, its ancestor/descendant, a filesystem root or a symlink/junction. No directory is created by the CLI.

```powershell
node --test tool/global_auth_account_qa.test.mjs
node tool/global_auth_account_qa.mjs --allow-isolated-qa-account --private-dir <absolute-private-directory>
```

- CLI accepts exactly those arguments in that order; no real contact, password or URL argument exists. Exit `0` means the authentication assertions and known-session cleanup were confirmed, `1` means partial/failed, `2` means opt-in arguments were absent/invalid.
- The sole output file is `<private-directory>/global-auth-account-qa.jsonl`, opened exclusively. First line contains the generated email/password, actual consent version and creation metadata. Remaining lines append fixed progress/cleanup fields, each flushed. No token/member ID is ever persisted. Read the **last complete line** for final state; do not mistake the first line's initial `accountMayExist:false` for the final state.
- Preserve the file even after failure. A second invocation in the same directory refuses before network access; it never retries registration or overwrites credentials. Only the operator may decide whether to use another dedicated directory after investigating the prior attempt.
- The sequence is GET gate → fresh no-code email capability → registration → member read → refresh → member read → old access and refresh rejection → logout → access and refresh rejection → password login → member read → final logout. POST 201 with envelope code 200 is accepted. The account remains for phone UI login; use its generated credentials, not a script token or device QA configuration.
- Before account creation, the second capability response must still identify exactly the smoke-validated consent version and both normalized legal-document paths. A change stops the run; no automatic retry or agreement to a newly published document occurs. Final logout and cleanup are not considered complete from a success acknowledgement alone: member reads must confirm denial, and the normal final flow also checks refresh denial.
- SIGINT/SIGTERM stop additional business steps and attempt bounded cleanup of known sessions. Forced process termination, a lost registration/refresh response, a failed cleanup or unreadable final journal prevents a complete assertion. `manualRecoveryNeeded:true` requires the server owner to inspect sessions for that synthetic account using the private record; never create another account to hide the incomplete run.
- The private record is plaintext by explicit design inside an operator-protected directory. Do not copy it into this repository/build archives, attach it to chat, print it, or pass its contents as shell/ADB arguments. Its initial credential line may be read directly into operator memory for authorized phone input.
