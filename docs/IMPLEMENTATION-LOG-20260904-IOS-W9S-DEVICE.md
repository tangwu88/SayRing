### 本轮发现的问题

#### P1-01：登录状态更新后保留旧连接，手动同步静默失效

- 复现现场：App 已显示 W9S 连接，登录资料从空恢复为完整字段；连接所属登录代次与当前登录代次不一致。
- 预期：登录完成后重新建立当前账号的设备会话，或清楚提示重新连接；不能显示可用连接却静默跳过同步。
- 实际：调用与“同步数据”按钮相同的 `syncDeviceData()`，立即返回；同步代次未推进，仍显示旧的“设备暂无新数据”，没有开始新的手表读取。
- 代码证据：`AppController._advanceSessionGeneration()` 推进登录代次并清理账号内存，但没有清除旧的 `connectedDevice` 和连接所属代次；`_syncDeviceData()` 在代次不一致时直接返回 `false`。
- 现场恢复：使用当前服务端真实个人资料，正常断开 → 扫描 → 精确连接同一 W9S；代次恢复一致，首次同步可执行。此为本次操作恢复，不是代码修复。
- 待修边界：保留账号隔离，不能简单删除代次校验。应在登录切换流程取消旧设备任务并安全重建/解除旧连接，同时增加同账号重新登录、换号、旧回调迟到的回归。

#### P1-02：双 SDK 路由漏接 iOS 原生表盘目录与下载

- 复现：iPhone 连接 W9S；已安装表盘和原生屏幕规格均读取成功；调用 `readNativeWatchFaceCatalog()` 两次。
- 预期：由当前 Vep 分支进入 Veepoo iOS 原生目录，目录和下载均绑定当前设备。
- 实际：客户端立即抛出 `UnsupportedError: 当前平台不支持原生表盘目录`，不是厂商接口超时或厂商空目录。
- 代码证据：底层 `MethodChannelWearableBridge` 已实现 `WearableNativeWatchFaceBridge`，但生产使用的外层 `RoutedWearableBridge` 没有实现/透传该接口；`usesNativeWatchFaceMarket` 的类型检查因而恒不满足。
- 影响：iOS 原生目录/下载分支不可达，页面还可能进入非原生目录回退路径；仅检测底层桥接的测试没有覆盖生产双 SDK 组合。
- 待修边界：补齐按当前活动 SDK 的目录/下载透传及换设备保护；Vep 才开放原生目录，Yuc 无授权时仍关闭商城，不通过强制返回 `true` 或套用 W9S 默认资料绕过门禁。
