# Say Ring 1322 心血管趋势模型联调

2026-11-25。以 App 提交 `3ee4947`（1321）为基线。1321 将本机统计填入预写文案。本次按用户要求接入后台已配置的模型，使解读随实际选定的记录变化。

## 用户看到什么

从「健康 → 健康数据 → 全部数据」打开最后一项「心血管趋势」。最近一次血压下方的「AI 趋势解读」先显示收缩压与舒张压的总体变化，再显示有同日记录的心率、睡眠和步数解读。下方的「数据摘要」「查看依据」和曲线提供可核对的测量值及日期。切换 7／30 天、结束日期、血压来源或界面语言会选择对应分析。游客仍可查看本机统计。

加载、失败和成功各有对应界面。请求超时可点「重新分析」。某段时间没有血压时跳过请求。只有单日或两期共同记录不足时，只报告能够支持的观察。

## 数据与模型

- `cardiovascular_model.dart` 按有效记录日分别计算两项血压的变化，逐项匹配同日的心率、睡眠时长和步数。两期各至少有三个有效日才比较均值。当前周期至少有三个匹配日才统计相邻两次观察中同向、反向和持平的次数。零步和缺少记录含义不同。上臂血压与穿戴设备分开，同一穿戴来源的数据单独计算。U19 沿用型号、固件和云端读回检查。
- 通过 `GlobalSaydianApiClient.analyzeCardiovascularTrends` 向第一方现网 `/global/api/saydian-app/v2/ai/messages` 提交固定结构的比较资料，使用独立的 `say-ring-cardio-trends-v1` 会话。后台取已配置的 AI 供应方和模型进行推理，保存回复后返回。输入限于时间窗长度、相对日序、日内汇总的相对位置、变化方向、来源类别和计数。绝对日期、原始读数、设备及会员标识不进入模型提示。第一方服务按现有会话机制在登录账号下保存提交的资料和回复。
- 页面只显示本次请求所需指标的结构化助手回复。账号切换后丢弃迟到回复。切换来源、周期或语言后，旧请求不会覆盖新页面；返回相同条件可复用当前页面的结果。模型请求失败仍可查看本机数据。

## 华为真机与回归

在已登录的华为 PPA-LX3 上运行 1322 源码，复用 App 的正常认证和网络客户端。专用调试入口 `tool/cardio_model_live_device.dart` 在内存生成两组测试资料，随后打开与正常入口相同的完整趋势页。测试未写入会员健康记录。测试入口与普通安装包的主入口独立。

| 实测 | 观察到的结果 |
| --- | --- |
| 7 天中文，每期 4 个记录日 | 网关 HTTP 201。模型指出两项血压均值较前期上升。在三个相邻记录间，心率和步数与血压同向，睡眠时长与血压反向。 |
| 30 天英文，每期 4 个记录日 | 网关 HTTP 201。两项血压和心率均值较前期下降，睡眠和步数均值上升。英文解读能区分本期共同变化和两期均值比较。 |
| 完整中文页面 | 网关 HTTP 201。实际「心血管趋势」页显示本次收缩压、舒张压、模型摘要及三个指标的解读。屏幕来源为「合成测试设备」。 |

首轮模型曾将一致方向说成混合趋势。增加精确的逐次变化计数，并要求明确比较周期后，上述三次实测均与输入相符。联调曾遇上游 HTTP 503 超时；后续真实请求成功。自动回归复现了点击重试时 Flutter 对异步 `setState` 回调报错的问题，修正后核对了失败、点击重试、成功显示和延迟结果隔离。
