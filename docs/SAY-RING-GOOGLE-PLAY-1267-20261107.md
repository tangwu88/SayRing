# Say Ring Google Play 首版 1267～1268（2026-11-07）

## 范围与基线

- 目标为独立的 Say Ring，包名 `cn.saydian.ring`；不是另外两个 SayDian 产品。原 iOS 1261 发布、1263 测试组与 XR 普通调试进程不改动。
- 隔离分支 `codex/google-play-release-1267-20261107`，iOS 基线 `226badef9ba903182a57d32d2ae82a9b4decb2a0`，合并 Android 最新 `a88c3c257178e5d9550242c3fe696f790d66bf58`（包含 1266）。保留两侧变更和既有历史，不将陈旧 main 覆盖到运行主线。
- 发行参数最终使用 `--build-name=1.0.12 --build-number=1268`，初次候选为1267；pubspec 默认版本不代表本次发行参数。
- 用户已明确允许创建 Google 条目、原正式签名通过官方 PEPK 加密托管、审核团队使用指定测试账号，以及完成 IARC 条款和内容分级。签名密码、审核密码、令牌、加密导出包及生产私有配置均不入 Git。

## 渠道实现与防复发

1. `AppDistribution` 由编译参数 `SAY_RING_DISTRIBUTION_CHANNEL` 固定渠道，默认 direct，只接受 direct/google-play；Google 行为仅在 Android 生效，不按账号、审核身份或服务器临时改变。
2. Play 包不执行站外 APK 更新：关闭自动探测与缓存强制安装门禁；手动更新打开确切包名的 Google Play 页面。Dart 下载/安装入口和 Android 原生安装、未知来源设置均先阻断，release overlay 移除安装包权限、旧更新 FileProvider 和广告标识权限。直装渠道保持原行为。
3. Play 首版关闭数字报告购买、价格和外部支付，不创建待支付报告。保留已有报告、有效次数和正常权益核验；实物商城、订单、售后保持独立能力门禁。
4. 原商城公开评价缺少完整举报、屏蔽和审核闭环，Play 首版统一关闭商品评价展示与订单发表入口，控制器也在请求前阻断提交。既有评价、订单和健康数据均不删除；其他渠道不受此编译策略影响。重新开放前需先补齐完整治理功能及对应申报，不能仅改 UI。
5. 合并时保留新扫描优先和有界系统缓存恢复。发现 `listBondedDevicesForSelection` 会清掉当前扫描结果，补充显式 `preserveCandidates` 供并行候选查询使用；默认行为仍兼容原调用，不绕过账号、目标或连接代次校验。

本轮未卸载、覆盖安装、清空手机或戒指；没有调整监测频率、提醒开关或设备时间，没有在生产写入测试健康记录。

## 执行检查与失败记录

- 初轮格式/分析出现私有初始化参数写法和未用 import 提示，修正后通过。
- 购买测试初轮缺 foundation 导入；补齐后又发现手动复位平台覆盖与 widget-test teardown 冲突，改用 `TargetPlatformVariant.only(Android)` 后通过，未修改产品的平台判断。
- 磁盘耗尽导致测试编译中止。确认未有 Xcode 编译后，仅删除已识别的闲置可再生成中间产物，保留源码、归档、最终安装包和设备备份；原失败及恢复记录保留于私有构建证据。
- 合并后首次完整测试 2108 通过、8 失败：5 个扫描回归揭示缓存查询清空新扫描列表的真实问题；另 3 个为测试替身缺新增购买能力 getter。修正后定向 71 项、完整上海/UTC 各 2116 项通过。
- Android 原生夹具首轮因 node 不在 PATH 未启动，改用受信任的本机 Node/JDK 17 后 42 项通过。这是宿主协议执行，不是实体戒指无线验收。
- 评价保护初轮编译发现异常构造器缺必需消息参数，补齐后 27 项定向用例通过。最终格式、静态分析、上海完整 2117 项通过；UTC 完整 2117 项也通过。
- 最终 AAB、Release APK、Debug APK 和 Android `testDebugUnitTest` 均通过。构建前后运行源码摘要一致，私有 `key.properties` 已在 finally 中删除。
- 发行检查首次错误地将 aapt XML tree 输入要求解码 XML 的检查器；改用 `apkanalyzer manifest print` 后通过。首轮 JPush 环境缺失和修正一并保留。
- 最终 bundletool 依赖清单解析初轮未剔除 CRLF 折行中的 CR，误把 `-1.6.2.jar` 当独立依赖；规范化 CRLF 后验证通过，原生二进制未因此修改。
- 最终包已核验：原 RSA 4096 正式签名、包名/版本、双 ARM、目标 API 36、16KB ZIP 对齐；22 个 arm64 ELF 的全部 LOAD 段均满足 16KB 对齐。受控 JPush `libjutils.so` ABI 例外与依赖报告、锁文件配套检查通过。
- 解码后的 APK/AAB 均不含 `REQUEST_INSTALL_PACKAGES`、广告 ID 权限、更新 provider 或 debuggable；bundletool validate 与 AAB 签名检查通过。
- iOS Debug/Profile 无签名兼容编译已串行尝试，均被当前 Xcode 27.2 的最低 iOS 15 与仓库 iOS 13 配置冲突阻断；不能写为通过。未为这次 Android 任务提高 iOS 最低版本，也未改动 Apple 发行、安装或 XR 进程，既有 1263 真机结果不被覆盖。

## 预检追加修复1268

- Google 对1267的预检发现“未选国家”和“必须声明精确闹钟”两项阻挡。地区按已说明的首发默认方案保存香港、澳门、台湾、新加坡四地，没有自动开放全球。
- 精确闹钟来自SDK合并清单，非本应用核心功能。仅在Play overlay移除 `USE_EXACT_ALARM` 和 `SCHEDULE_EXACT_ALARM`，不提高权限或虚报闹钟/日历用途。周期通知原本使用普通 `AlarmManager.setWindow`，即时健康提醒不依赖精确闹钟；戒指设置不改。
- 1267已被Google接收，因此递增为1268重建；只移除草稿中的1267关联，Google制品库仍保留原文件，不涉及用户数据删除。
- 1268的原签名AAB、Release APK、Debug APK和原生单测均重新构建通过；包名、版本、API36、清单、原签名、双ARM、ZIP16KB和bundletool检查重新通过。所有原生库与已检验的1267逐字节一致，包含22个arm64的16KB ELF结果，没有改第三方二进制。
- Play清单是1268相对最终1267的唯一运行源码变化；Dart保持双时区各2117项通过时的内容。最终APK/AAB均确认没有两项精确闹钟权限，Google预检结果另行记录。
- 更新中文交付记录时，一次私有辅助脚本因stdin编码解析失败未修改文档；保留该失败，改用UTF-8补丁更新记录，未改运行源码或制品。
