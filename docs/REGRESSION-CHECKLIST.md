## 1. 修改前：Git 与现场保护

- [ ] 执行 `git status --short --branch`，确认哪些改动属于当前任务。
- [ ] 执行 `git fetch --prune origin`，记录本地、当前分支、`origin/main` 的提交号。
- [ ] 工作树干净且无分叉时才执行 `git pull --ff-only`。
- [ ] 工作树不干净时先保留现场，不覆盖、不回退、不把来源不明文件纳入提交。
- [ ] 原型、交付 ZIP、小程序源码和真机健康记录保持只读。

## 2. 修改前：避免并发构建互相破坏

- [ ] 执行 `ps -axo pid,command | rg '[f]lutter run|[x]codebuild|[g]radle'`。
- [ ] 同一仓库存在 iOS 构建时等待其完成，不并行运行另一个 `flutter build/run ios`。
- [ ] 出现 `.pcm`、`.scan` 或 DerivedData 临时文件缺失时，先排查并发，不先改业务代码。
- [ ] 需要清缓存时只处理已确认的项目缓存路径，优先移动为可恢复备份。

## 4. 设备与健康数据固定检查

### 账号隔离、升级迁移与鉴权

- [ ] 健康、运动、预警、元数据、同步游标和消息收件箱的每次读写都显式携带稳定账号 owner。
- [ ] 换号时先推进登录代次；上一账号的同步、网络响应和原生迟到回调不能写入当前账号。
- [ ] v5 无账号数据先标记为 `legacy-unscoped`，仅升级启动时已持久化账号可以认领。
- [ ] secure vault 中的一次性 migration marker 与数据库事务结果一致；首次迁移未登录时也写入 marker。
- [ ] 首次迁移未登录后再登录任意账号，遗留数据仍保持未归属且不会被后续账号继承。
- [ ] 旧健康、运动、预警、元数据、游标和消息在同一事务内完成认领；失败时不得出现半迁移。
- [ ] 升级后首次账号可读取旧记录，之后登录的第二账号看不到也不能再次认领这些记录。
- [ ] 同账号并发 401 只触发一次刷新；刷新结果提交和请求重放都通过账号、旧 Token、登录代次 CAS。
- [ ] 账号 A 刷新期间登录账号 B，A 的迟到 Token 不覆盖 B，也不以 A 身份重放原请求。

### 设备标识

- [ ] iOS 连接键继续使用 CoreBluetooth UUID。
- [ ] 只有经过校验的厂商地址显示为 MAC；否则显示“iOS 连接标识”。
- [ ] Vep/Yuc 标签与实际 SDK 路由一致。

### 心电

- [ ] 实时 App 测量来源为 `app_measurement`，手表历史为 `watch_history`。
- [ ] ADC 经过厂商换算后才绘制；缺失或低质量样本不伪造波形。
- [ ] 没有波形时仍可展示设备明确返回的心率、HRV、QT。
- [ ] Android 测量覆盖启动、接触宽限、停止、150/160 秒完整周期和蓝牙中断。

### 远程关爱

- [ ] 角标数量等于待处理列表实际数量。
- [ ] 分享权限默认关闭，已有服务端授权保持原值。
- [ ] 单项接口、原始日记录和聚合摘要的优先级没有颠倒。
- [ ] 接口失败、无数据、未授权不显示为 0 或“正常”。
- [ ] 心电只展示远程成员字段和真实可用波形，不输出原始 JSON 键。

### Android 历史同步

- [ ] 串行顺序为睡眠 → Origin/OriginData3 → 手动测量历史 → 心电历史。
- [ ] 检查半小时心率、半小时血压和手动血压的收缩压/舒张压/脉搏。
- [ ] 检查心率、血氧、体温、血糖、HRV、身体成分、血液成分和心电映射。
- [ ] 同秒重复记录合并字段，连续同步不增加重复记录。

### 运动与预警

- [ ] 运动入口只显示设备实际上报且桥接实现的模式。
- [ ] 活动中退出必须确认；暂停、结束和本地轨迹保存不丢失。
- [ ] 预警只来自明确事件或最近可靠记录，不做疾病诊断。
- [ ] 历史同步重复执行不会生成重复预警。

### 表盘

- [ ] 本地已安装表盘使用 `switch + imageId`。
- [ ] 在线表盘使用 `upload_network + 文件元数据`，传输完成后读取设备状态确认。
- [ ] 设备协议、最大长度、表盘形状或在线能力缺失时不展示在线商城。
- [ ] 传输失败、超时、蓝牙断开和设备拒绝均显示真实错误，不伪报成功。
- [ ] iOS 在线目录和下载只经 Veepoo 原生 `VPMarketDialManager`，不得回退到 Android 目录或直接下载链路。
- [ ] iOS 原生目录 ID、真实文件路径和长度绑定当前连接代次及设备 profile，换表后的旧结果被丢弃。

### 原生耗时命令互斥

- [ ] 电量读取、健康历史同步、测量和表盘传输使用同一厂商 SDK 命令互斥，不能并发抢占。
- [ ] 电量读取 8 秒、表盘传输 150 秒、历史同步 180 秒等一次性超时按当前实现覆盖；完成、失败、断连均释放锁。
- [ ] 迟到回调只结束自己的连接代次和任务令牌，不能更新新设备状态或释放下一任务的锁。

## 8. 通知、消息收件箱与推送

- [ ] 新本地事件写入后，用陈旧远端未读缓存刷新，事件仍保持未读且数量不会被错误压低。
- [ ] 本地与远端按稳定事件 ID 合并；重复推送不重复入箱，已读状态重启后仍保留。
- [ ] 健康预警和关爱邀请分别覆盖前台、后台、进程终止后点击，以及未登录后登录续跳。

- [ ] 用户拒绝系统通知权限后，应用内消息、红点和前台提示仍可用，并提供系统设置入口。

### 载荷与隐私

### 凭据与环境

## 9. 表盘与 iOS 电量

### 表盘兼容资料和缓存

- [ ] `watchuiCoustom` 只表示自定义表盘数量，代码和测试都没有将其用作 `dialShape`。
- [ ] 商城 profile 同时包含厂商、设备标识、名称、设备号、固件、屏幕宽高、形状、协议、最大长度、槽位和兼容指纹；缺项时不开商城。
- [ ] 未知设备不会套用 W9S 默认 profile，商城标题来自当前连接设备或显示“适配当前手表”。
- [ ] 换表、断连和重连后旧 profile、目录及缩略图缓存被清空；离线缓存按兼容指纹隔离。
- [ ] 传输前再次核对当前设备、兼容指纹、尺寸、协议和文件长度；设备已变化时中止。
- [ ] 传输完成后回读当前表盘路径或 ID，一致后才显示成功；超时、拒绝或回读不一致均显示真实错误。
- [ ] 缩略图只使用 SDK 本地图片、目录匹配预览或用户照片预览；没有真实资源时显示“预览暂不可用”。

### 临时表盘真机测试

- [ ] 安装前记录手机、手表、时间、原表盘路径/ID、临时目标和当前连接代次。
- [ ] 测试结束恢复原表盘，并通过设备回读确认路径/ID 一致；恢复失败登记阻断并保留日志。
- [ ] 未完成原表盘恢复前，不继续下一台设备测试，也不把该项标记为通过。

### iOS 电量

- [ ] 百分比设备按百分比显示，四格设备按 `n/4 格` 显示；`3/4 格` 不显示为 `3%` 或推算成 `75%`。
- [ ] 电量状态同时验证数值、刻度/百分比类型、低电、充电和更新时间。
- [ ] 连接 A 发起读取后切换到设备 B，A 的迟到回调不能覆盖 B；连接代次不匹配时丢弃回调。
- [ ] 断连清空当前设备电量；超时只显示旧的同设备有效值或未知，不误报设备断开。
- [ ] 电量读取与心电、历史同步、表盘传输不并发抢占 SDK 命令。

## 10. 在线升级与发布原子性

### 客户端升级

- [ ] 更新清单分别覆盖 200、404、超时、非 HTTPS、JSON 格式错误、字段缺失和平台不匹配。
- [ ] 清单获取或校验失败时不进入强制更新；仅在有效新清单明确 `currentBuild < minimum_supported_build` 时强更。
- [ ] iOS 生产目的地只能是具体 `apps.apple.com` 产品页，并交给 App Store；不得下载或安装 IPA。
- [ ] Android APK 下载支持重试，安装前校验 SHA-256；损坏文件删除，不交给系统安装器。
- [ ] Android 从正式同签名旧包升级到新包后，登录、本地健康记录和设置不丢失；包名或签名不一致时发布门禁失败。
- [ ] Android 未授权“安装未知应用”时只引导到当前 App 的系统授权页，不绕过系统校验。
- [ ] 启动自动检查与“关于我们”手动检查共用应用根级 Gate；页面关闭、重建或持久化失败不能解除必要更新。
- [ ] 清单和 APK 的每次重定向及最终有效地址都重新校验为同源 HTTPS，跨域、降级 HTTP 或凭据 URL 立即拒绝。

### 发布流程

- [ ] 发布任务先取得互斥锁；已有有效发布占用时当前任务停线，不并发覆盖线上清单。
- [ ] 发布前读取公开清单哈希，远端替换执行 CAS；哈希不一致时停止，不覆盖他人新版本。
- [ ] APK/商店目标先发布为不可变资源，校验可达和 SHA 后才原子切换公开清单。
- [ ] 切换后从公开地址重新验证；失败时恢复旧清单，并再次验证恢复内容与原哈希一致。
- [ ] 锁和临时文件在成功、失败与取消路径都清理；过期锁只按文档化恢复流程处理并保留审计记录。
- [ ] 生产发布缺少公开清单地址、Android 正式签名、具体 App Store 产品页或推送凭据时硬失败，不以“稍后配置”继续上线。
- [ ] Android Release Manifest 不含后台定位、读取电话状态和查询全部应用权限；新增插件后重新检查合并结果。
- [ ] APK 原生库默认要求 `armeabi-v7a`/`arm64-v8a` 对称；只允许锁定 JPush/JCore 组合下 `libjutils.so` 的精确例外，依赖版本变化时重新停线审计。
