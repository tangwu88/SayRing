# XR 系统已连接 R8，添加和恢复列表遗漏

2026-11-02。在 iPhone XR 的普通 Say Ring 1.0.10（1226）复现，修改基线为 `5e5c596`。本轮验收对象是同一枚 R8 在两个手动入口的可见性。截图、设备标识和原始蓝牙观测仅保存在本机忽略目录。

## 修复前的对照

- XR 的「设置 → 蓝牙」显示 `SD_RING_R8` 已连接。普通 App 手动「重新搜索」只列出 HR05、R7y，点「显示可恢复的戒指」只额外列出 R21。首次自动化未找到按钮，按实际页面的按钮重跑并分别留存两个入口的结果。
- 保持原蓝牙状态，用独立只读程序在同一台 XR 同时核对广播、系统连接和先前验证过的精确标识。第二轮 22.4 秒收到了来自 31 台设备的 1,498 次广播回调，R8 的名称、设备标识和已知厂商地址均未命中。HR05 和 R7 有广播。
- 普通版本所查的厂商服务以及通用 HID、GAP 服务均未返回目标。改查戒指实际提供的 `DE5BF728-D711-4E47-AF26-65E3012A5DC7`、`6E40FFF0-B5A3-F393-E0A9-E50E24DCCA9E`，首尾查询均返回名称和标识匹配的 R8。系统返回的外设对于查询方仍处于未连接状态。苹果允许枚举其他客户端的系统连接，本 App 仍需单独连接才能使用设备。[Core Bluetooth 接口说明](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/retrieveconnectedperipherals%28withservices%3A%29)
- 搜索和恢复共用的 iOS 原生枚举漏查上述服务，且过去还要求本 App 已经连接。恢复列表另有一层提前结束逻辑：当前账号一旦找到一个缓存候选，就跳过系统枚举。本轮原界面的恢复结果有 R21。这些条件共同解释了两个入口的表现。

## 修改和验收范围

- 普通搜索及手动恢复均查实际厂商服务。系统返回且名称符合路由的候选可以手选，广播信号未知时不提供强度。通用服务仍沿用原有筛选条件。
- iOS 将当前账号的缓存候选放在前面，再合并系统已连接的候选，按通道及设备标识去重。已有缓存的情况下，补查失败或超时也可继续选择缓存项。自动恢复仍要求当前环境、账号、精确目标和新的设备握手；手动展示列表不会写入绑定。
