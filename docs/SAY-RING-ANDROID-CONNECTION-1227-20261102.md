## P1: ordinary reconnect removed the system bond

Reproduction: on the connected R21 device page, tap Reconnect. Expected: preserve OS pairing and the app binding, retire the old native session, then perform a fresh exact-target handshake. Actual on formal 1226: first UI-observed recovery took about 59 seconds; the second had not recovered after 65 seconds. Native logs showed GATT failures and repeated `createBond` requests. UI polling includes observation overhead; these are not precise radio timings.

The Android bridge used `BleOperateManager.unBindDevice()` for ordinary disconnect. Inspection of the bundled, unchanged SDK confirms that this API asynchronously removes the OS bond, whereas `disconnect()` uses `disconnectDeviceKeepBond`. The SDK's actual disconnect callback clears pending response parsers, local writes and scheduled/direct tasks. The keep-bond implementation can publish that callback before a bonding GATT has physically closed, so a disconnect broadcast alone must not release the cancellation barrier.

Changes are limited to `QRingBridge.java`: disable independent SDK reconnect, cancel pending work before the current task, use the keep-bond disconnect, retain the cancellation barrier on exceptions, and confirm actual SDK/GATT closure before allowing the next session. New production-method and bundled-SDK contract regressions cover bond preservation, stale work, duplicate cancellation, delayed closure, exceptions and late callbacks. The bundled SDK, iOS runtime, shared Dart logic, server and release scope are unchanged.
