# 2026-09-28 HR01 实机连接、健康与运动调试

## 修改原因

在“首页、健康、设备与独立下载页更新”完成后，使用已佩戴的 HR01 和华为 Android 真机继续做现场调试。重点核对压力、HRV、设备控制入口、戒指文案、运动页面与实际启停流程，不能用自动化通过代替真实戒指回调。

## 调试环境

- App：Say Ring `0.1.21 (1004)`，包名 `cn.saydian.ring`。
- 手机：华为 Android 真机，通过 USB 覆盖安装，保留原登录和本地数据。
- 戒指：HR01，固件 `758.0.1.9.0`；调试期间处于佩戴、贴合状态。
- 第三方 App：只临时停止可能占用蓝牙的进程；未解绑、未清除数据。HBand 在收尾后已恢复系统默认启用状态，`enabled=0`。
- 真实健康结果属于现场隐私数据，本记录只写“收到有效值”，不保存具体数值。

## 问题、复现与修复

### 1. 设备控制入口被隐藏

- 复现：HR01 已连接且原生桥已识别查找、相机、自动健康检测能力，但 Flutter 设备页没有显示对应入口。
- 根因：CoolWear 原生能力结果只有 `features`，遗漏 Flutter 能力交集需要的 `integratedFeatures`。
- 修复：把原生桥确实已接入的能力同步到 `integratedFeatures`；仍保留设备握手能力门禁，不把 SDK 中存在但当前硬件未声明的能力伪装为可用。
- 实机结果：设备页显示“查找戒指、相机遥控、健康监测、关于设备”。

### 2. 压力测量一直没有结果

- 首轮复现：压力命令已发出，但 HR01 在测量窗口内断开；页面正确停止并提示重连后重试，没有保存未知值。
- 重试结果：连接稳定窗口内收到 SDK 的真实 HRV 兼容压力回调，页面显示有效压力结果和说明。
- 修复补充：仅 Debug 构建记录回调来源、设备时间与有效性，Release 不记录健康数值；没有增加随机值或默认值。
- 结论：压力链路实机通过，但 HR01 蓝牙仍可能每隔几十秒到数分钟断开并自动重连，断线时需重试。

### 3. HRV 新命令在 HR01 上不回调

- 复现：文档推荐的 `sendRriHrvCmd(OPEN)` 在多次连接窗口内未返回，且链路会中途断开。
- SDK/LuckRing 对照：当前 SDK 同时保留新 RRI-HRV 命令与 LuckRing 使用的旧实时 HRV 命令；安装包反编译只用于确认调用路径，没有复制随机压力算法。
- 修复：先发新命令；8 秒仍无结果且连接有效时补发旧 HRV 兼容命令。停止、断线、完成和销毁时均取消延迟任务并关闭两条命令路径，防止迟到回调串入下一次测量。
- 实机结果：兼容命令返回有效 HRV，页面显示 `ms` 单位和趋势提示；数据来自戒指回调，不以压力值或随机值代替。

### 4. 首页文字在窄屏省略

- 复现：首页 `Say Ring 商城` 被显示为省略号，部分健康卡标题/状态也存在截断风险。
- 修复：入口标签、健康指标标题和状态胶囊保持单行，并只在空间不足时等比缩小。
- 实机结果：首页商城文字完整显示；最终卡片微调由页面测试和最终安装包继续覆盖。

### 5. 相机页面仍有手表按键文案

- 复现：相机遥控页提示“按戒指拍照键”，但 HR01 无屏幕、无拍照按键。
- 修复：统一改为“点击手机快门或摇动戒指触发拍照”，并增加源码防回归检查，禁止再次出现“按戒指拍照键”或“戒指弹出确认”。
- 实机结果：相机页可打开并完成相机初始化；本轮没有现场观察到一次摇动触发成片，因此物理手势仍列为待验，不把页面可达写成硬件触发通过。

### 6. 健康测量仍有“按戒指提示”文案

- 扫描发现体成分/血液成分等待提示仍要求用户“按戒指提示接触电极”，不符合无屏 HR01。
- 修复：改为按手机页面指引调整接触位置并保持戒指贴合；防回归规则新增禁止“按戒指提示”。

## 失败、修正与边界

- 项目没有服务端约定中的 `tools/Start-Change.ps1`；改为逐项执行分支、工作树、远端与提交号检查，不能声称运行了不存在的脚本。
- 首次调用的 Flutter 路径不可用，改用项目现有工具链 `E:\saydian\.toolchains\flutter`。
- 首次 `JAVA_HOME` 指向 JDK 上级目录，修正为 `E:\saydian\.toolchains\jdk17\jdk-17.0.20+8` 后通过。
- 提交前第一次 `git fetch origin --prune` 收到 GitHub 空响应；重试成功后再继续核对远端提交，不把首次失败写成已同步。
- 华为首轮安装确认时风险复选框未实际生效，系统返回 `INSTALL_FAILED_ABORTED: User rejected permissions`；第二轮逐页确认复选框和按钮状态，再完成锁屏密码验证后安装成功。
- 扫描到的 `TK65 9061` 不是本轮 HR01，没有把邻近设备误当目标戒指。
- LuckRing 首次查看也未立即显示戒指，稍后才自动重连；这与 Say Ring 观察到的 HR01 链路波动一致，但不能据此把波动原因归咎于某个 App。
- Windows 无法执行 iOS 构建；本轮也没有重做 HarmonyOS 原生构建。共享 Flutter 页面与 Android HR01 桥的结果不能冒充 iOS/HarmonyOS 真机通过。
- 构建提示 CameraX 与极光插件仍使用旧 Kotlin Gradle Plugin 应用方式；当前构建成功，但需在未来 Flutter 强制 Built-in Kotlin 前升级插件。
