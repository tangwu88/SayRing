# 客户端源码审查与防复发门禁

适用于 Say Ring 的 Flutter、iOS、Android 和原生 Harmony。修改前阅读本文件、当前 AGENTS、REGRESSION-CHECKLIST 和最近变更记录；以当前产品要求为准，不直接复用导入项目的旧包名、默认版本或发布说明。

本文件是长期检查要求，不是“所有问题已修复”的证明。检查结果分为已查、已测、待实物、未覆盖；发现问题必须有触发条件、预期/实际、优先级、证据和关闭标准。详细安全发现及用户/设备诊断保存在私有工作记录，不上传公开仓库。

## 1. 先固定基线与操作范围

- 检查 branch、HEAD、工作树和 origin，fetch 后仅在干净当前分支快进；保留其他人的改动，禁止强推或清理用户文件。
- 明确本轮是源代码审查、功能修复、构建、安装还是发布。上一步成功不能代表下一步完成。
- 源码审查不主动修改账号、生产配置、戒指绑定、手机数据或实际支付状态。需要故障注入时先用独立合成夹具，不对用户密钥/数据库做破坏性试验。

## 2. 账号、异步与生命周期

- 每个异步操作都捕获 owner、session generation、目标与 operation generation；返回、catch、finally、延迟任务、原生回调和持久化前重新核对。
- 旧操作不得清除新会话、复活旧凭证、改写新目标或提前释放另一操作的 busy。共享会话写入/清理要有比较后提交或串行规则，不能仅靠页面按钮禁用。
- 退出、删除、刷新、重复点击和新登录交错必须有单飞/幂等测试；验证原请求迟到、失败、页面销毁及账号替换的实际结果。
- 所有持久化读写显式带稳定 owner。查询到的数据、页面列表计数与数据库原始留存是不同证据。

## 3. 安全存储、迁移与数据保留

- 安全存储的配置必须统一审查所有消费者，并核对锁定依赖的真实默认值、迁移、错误恢复和备份行为；不能依赖“默认安全”的假设。
- 错误恢复不得静默丢弃仍被旧加密库使用的密钥。区分新安装、暂不可读、旧库缺密钥和待恢复；迁移需可中断、可恢复并可验证原 owner 数据仍可读取。
- 保数据测试不得默认卸载、恢复出厂或清理容器。按既有约定先私有备份；SDK ACK、文件仍存在、页面显示最近记录均不能单独证明完整数据留存。
- 校验升级前后全部必要记录 ID、owner、来源、设置和可读性；日志不得输出密钥、认证头、真实健康值或用户标识。

## 4. 蓝牙连接、实际能力与物理操作

- 名称只选择候选适配器；当前真实握手和能力决定功能。不得按旧健康记录、其他型号或默认值恢复入口。
- 自动恢复只使用当前环境/owner 最后成功握手的精确目标；目标替换、退出、撤权及权限变化必须退役旧回调。
- 系统适配器状态、无线连接、SDK 握手、能力准备、数据同步分别建模。覆盖关/开蓝牙、系统服务重置、缺失/重复回调、后台恢复、旧对象失效及旧回调迟到。
- 实际关闭之前保持取消屏障；连接超时不等于无线已关闭。避免重复准备、无限快速重试或复用未清理的失败会话。
- 无数据/不开放历史按产品要求静默结束，不能用提示替代同步，也不能把空结果当成读取完整的证据。
- 设置和振动等物理写入必须绑定精确目标、保存原设置并确认回读；含糊结果不自动重放。指令接受、SDK ACK 和实际振动/拍照/媒体控制分开验收。

## 5. 权限、授权期限和展示

- 服务端、Dart、原生 ceiling 与真实设备能力取交集；默认、失败、过期和撤权均关闭额外能力，不复活旧授权。
- 明确共同单调截止时间和剩余有效期；等待网络、原生确认或排队不能重新获得完整期限。验证部分确认、确认迟到、到期中途和墙上时钟变化。
- 模块显示、只读、手动测量、上传、购买是独立权限。显示入口不授权采集/上传，清理 stop 不能被新的启动门禁阻断。

## 6. 健康、活动、睡眠与提醒

- 保留原始来源、单位、时间与稳定 ID；未知值不补零，未知热量单位不猜倍率，去重要合并信息并可追溯。
- 上传仅接受实际批次内合法确认；额外/重复 ACK、取消和账号变化不能使未确认记录显示成功。
- 健康提醒只处理符合当前规则的新鲜、有效、完成测量。历史、导入、未来、未知、错误 owner/设备/固件/单位和预览不得生成真实提醒。
- HRV/皮温仅按明确个人参考比较，不推断心梗或核心体温；声音、动效、通知和戒指振动分别验证，支持结束/后台清理和减少动态效果。
- 用户预览不写真实事件/消息，不自动联系任何人；仅按已授权范围请求当前支持设备的一次有界振动。

## 7. 网络、通知、内容与商城

- 第一方生产请求保持精确 global 来源/路径，资源按目的白名单；拒绝不受信任跳转、路径逃逸和跨产品包。调试工具不得放宽正式构建。
- 通知队列与延迟任务绑定 owner/目标/代次；切换或失效即丢弃。消息内容、令牌与设备标识不写公开日志。
- 内容渲染、文件导出和外部链接分别检查脚本/公式/路径注入与允许目的地；不能以文案检查代替实际解析路径。
- 商城结果必须匹配当前账号/请求；支付成功等待服务端交易确认。客户端 SDK 返回不直接授予权益，不为测试发起真实付款。

## 8. 更新与发行

- 区分检查失败/不可用、已最新、有可选更新及必须更新。只有合法匹配的清单可以更正缓存状态；失败不能冒充成功检查。
- 核对实际包内产品、平台、包名、版本、签名、source SHA、产物 SHA-256 和发布目的地；历史交接资料和默认 pubspec 不能代替产物核验。
- 构建、安装完成、运行附加、真机功能、TestFlight 上传、审核提交、审核通过与公开下载分别记录，不能跨级推断。

## 9. 测试与关闭要求

- 定向测试必须断言预期业务终态，并补迟到、重复、撤销、目标/账号替换、失败和部分成功反例。诊断打印、编译成功、不抛异常不能代替完成断言。
- 复现当前错误的测试应明确标记；修复后改成期望安全行为，再撤回修复确认跑红。不得把“成功复现错误”计为“修复通过”。
- 记录原失败、夹具错误、修正与最终结果，不删失败记录。使用真实生产方法的宿主模型也要说明哪些系统/SDK行为是模拟的。
- 提交功能改动前按现有门禁完成静态分析、全量双时区 Flutter、相关原生/Harmony 测试和构建；文档审查不伪造新构建或实物验收。
- 真机结果固定手机/OS/戒指/固件、前后台、操作和观察，备份及保数据独立核验。普通重连通过不能替代静置连接，宿主测试不能替代物理效果。
- 未覆盖的第三方二进制、依赖公告、历史秘密扫描、设备矩阵和真实支付明确列出；不能据一次审查声称没有漏洞。

## 10. 每项问题的重点记录

```text
编号 / 状态 / 日期 / 代码基线：
触发条件、复现步骤、预期、实际：
影响等级与确定性（确认 / 有条件 / 待验证）：
源码调用链与证据位置（敏感材料私有）：
修改范围、所有关联消费者、保数据与权限边界：
原失败 / 修复后 / 撤回修复结果：
全量回归、构建与精确真机范围：
修复 SHA、剩余限制、关闭标准与复核结果：
```

状态应从 OPEN → IN_PROGRESS → FIXED_PENDING_DEVICE（需要实物时）→ VERIFIED 逐项推进；写了记录、测试数量增加或构建成功都不能直接关闭。
