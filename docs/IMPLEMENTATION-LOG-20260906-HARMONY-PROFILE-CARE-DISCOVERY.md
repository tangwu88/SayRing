# 2026-09-06 鸿蒙资料、关爱与设备发现整改

## 修改前状态

- 基线 `e3ffd36`，分支 `codex/harmony-native-login-home`；已执行远端更新，本地与上游一致，工作树干净。
- 用户现场反馈：个人资料页布局异常且不能编辑/换头像；关爱成员数据无法查看；附近有手表但添加设备为空；“我的”人数与关爱列表不一致。
- 本轮以当前 iOS/Flutter 产品页交互为参考，不修改 iOS 原始页面和用户数据。

## 安全边界

- 关爱真机只读取，不增删成员、不修改授权；不把空数据生成测试健康值。
- 头像真机只验证选择器可打开/取消和合成传输契约，未经用户选图不上传或覆盖真实头像。
- 设备诊断不记录设备地址、广播原文或账号；W8 仍强制归为 Yuc，未支持时不进入假连接。

## 执行记录

### 个人资料与头像

- 资料卡改为进入真实编辑页，按 iOS 信息层级重排头像、注册手机号和基础资料；昵称、性别、生日、身高、体重均可编辑，注册手机号只读。
- 使用鸿蒙系统图片选择器和裁剪能力；图片先校验格式与 6 MB 上限，再通过鉴权 multipart 请求上传，只有服务端返回有效同源路径或 HTTPS 地址后才保存头像。
- 真机已验证资料页布局、字段、保存入口以及图片选择器打开和取消；为避免改变真实账号资料，本轮没有选择图片、上传头像或提交资料写入。

### 关爱成员与人数

- “我的”摘要和关爱列表统一使用同一份服务端成员列表，并在登录恢复、回到前台和进入“我的”时刷新；请求带账号/代次校验，迟到响应不能覆盖新账号。
- 真机同一账号的“我的”显示 `2 人`，关爱页显示“已关爱 2 位家人”，并显示相同的 2 条成员记录，数量已一致。
- 成员详情一次读取当日原始响应，再逐项归一为“有记录 / 当日暂无记录 / 对方未授权 / 服务暂不可用”，不再把空数据和接口错误混在一起，也不伪造健康值。
- 两位真实成员的当日接口，以及其中一位前一日接口均返回 HTTP 200；10 项指标实际记录数均为 0，所以页面正确显示“可查看 0 项 · 暂无记录 10 项 · 未授权 0 项”。客户端查看链路已恢复，但非空健康值仍受服务端/数据源没有记录阻断。

### 设备发现

- Vep 扫描先把系统原始 `ScanResult[]` 交给官方 SDK 解析，再合并 SDK 结果、BLE 已连接设备和 HID 系统连接设备；W8 仍强制标记为 Yuc，随机标识不冒充 MAC。
- 增加官方服务 UUID 扫描和用于发现 W8/Yuc 的通用扫描，连接设备轮询间隔为 500 ms；扫描空态改为提示用户打开手表配对页。
- nova 14 多轮实测分别收到 406/404 次扫描回调和 12/13 个附近设备，诊断轮也能稳定发现附近蓝牙外设，说明手机权限、蓝牙和扫描链路有效；但系统与官方 SDK 均未上报 ET488、W9 或 W9S。
- 结论：代码侧扫描覆盖已补齐；目标手表必须解除其他手机占用并进入可发现/配对状态后再做连接、同步和测量验收。没有广播证据时不把普通蓝牙外设误识别为手表。
