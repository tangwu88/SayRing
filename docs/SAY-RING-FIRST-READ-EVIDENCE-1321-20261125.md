## 实现

- 协商摘要V3，服务端未明确提供V3时仍发送V1/V2。只有登录与隐私允许、服务端确认当前账号唯一首次资格、当前目标/会话仍匹配且摘要未冻结时，控制器才请求原生分项计数；权限返回晚于读取启动时保持普通读取，不阻塞蓝牙，也不在后续连接补采。
- Android CoolWear原生只在明确opt-in的本次历史读取窗口分配计数器。现有请求、有效历史DATA观察和纯记录映射位置增加有界计数；未匹配当前请求的包、无法确认为RRI的61响应不计。结束或失败释放窗口，不新增SDK命令。
- 可见分项为请求次数、包次数、包声明条目数与范围终态；心率/血氧/皮肤温度另记录实际解码、映射、过滤数量。其他指标映射未插桩时明确mappingObserved=false，后台显示未观察，不能从0推断没有记录。计数可含重复包，不是去重后的健康记录数。
- 校时快照仅来自现有同连接调度状态，发送尝试绝不标成ACK或读回成功；没有额外读时钟。监测开关只传现有已取得的心率/血氧布尔值，未知则不传。
- 严格白名单递归校验，计数0至1000000，最多7指标；不上传读数、测量时间、原始包、地址、记录ID、凭据或自由文本。保留4096字节上限，七指标加全部阶段的合成报告预算测试通过。
- 首次报告冻结后深拷贝且不再收集；账号切换、取消或旧回包沿用精确目标/代际保护。设备不支持此可选接口时普通健康读取不变。
