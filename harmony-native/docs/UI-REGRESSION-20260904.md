## 新问题：H-08 短页面顶部入口随内容高度跳动（P2）

- 复现：已登录首页 → 健康百科 → 带图文章，分别观察列表和图片加载前后。
- 预期：标题/返回入口固定在内容区顶部，内容从上向下展开。
- 实际：列表返回按钮 top=819 px；图文加载中 top=318 px，加载完成后 top=639 px。Scroll 默认居中导致内容高度改变时整体偏移。
- 原因：Index 的 Scroll 未指定顶部对齐。
- 修改：仅 Index 的登录、首页和内容 Scroll 对齐；增加布局约束回归。资料、登录、文章接口不变。
- 当前已验证：原有百科列表返回 4 个入口、带图文章的 2 张原生图片均实际显示；这两项不是健康内容质量审核。

## 新问题：H-09 文章详情沿用列表标题（P2）

- 复现：健康百科列表点击“了解血氧”；正文正确显示对应文本，但标题仍是“健康百科”。4 篇文章切换同样沿用旧标题。
- 服务端复核：四次只读请求返回的 id 和 title 均与请求一致，不是服务端返回了错误标题。
- 原因：`@Builder Heading(title: string)` 传值后未随父状态刷新；Notice 的动态提示同样存在传值风险。
- 修改：Heading 直接观察页面状态；Notice 改为单对象按引用参数；标题放在正文 Scroll 外，使阅读长协议时始终可返回。
- 官方依据：[ArkUI 参数传递与 UI 刷新说明](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-arkui-1546)。
- 影响范围：原生页面标题、提示与正文布局；无接口、账号数据或其他平台改动。
