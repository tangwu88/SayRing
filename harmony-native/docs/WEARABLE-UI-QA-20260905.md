# 原生鸿蒙 Vep 手表与苹果版页面对齐 QA

## 结论

本轮完成官方 Veepoo 鸿蒙 SDK 接入，并在华为 nova 14、HarmonyOS 6.1、API 24 上用 W9S 完成主要真机链路。鸿蒙首页、商城、健康数据、运动、设备和“我的”已按苹果版的功能信息架构调整，不做像素级视觉复刻。

当前包可用于已授权真机继续测试，但签名 Profile 类型仍是开发调试。服务端推送、支付、更新清单和 AppGallery 页面未齐，不能标记为正式上线版。

## 开工与依赖

- 开工基线：分支 `codex/harmony-native-login-home`，提交 `e92c0af`；修改前已完成远端更新且无分叉。
- 官方依赖：`@veepoo/vpble-sdk` 1.0.0，自包含 HAR 的 SHA-256 为 `60cdffa08076d7167e90736cd8ea433b62dbf562d295c5275acfc4bfcdd40bd2`。
- 只引入 SDK HAR，不复制示例工程的厂商签名配置；本机证书、Profile 和密码没有进入源码。
- 名称中包含 `W8` 的设备始终归为 `Yuc`；其他符合官方广播规则的设备归为 `Vep`。

## 真机结果

测试设备为华为 nova 14（HarmonyOS 6.1，API 24）和 W9S。真实 MAC 在 UI 正确显示，本文只保留脱敏标识。

- Release 覆盖安装成功，版本 0.1.3（4），`debug=false`；登录态和本地数据保留。
- 冷启动后恢复 `SD-watch-W9S`，电量约 75%，读取到真实型号与固件，并自动同步到 2026-09-05 13:36。
- 手动同步、刷新、电量、同步时间、查找设备、读取设置均成功；连接在页面切换和前后台恢复中保持稳定。
- 心率、血压、血氧、体温、心电和身体成分的开始/取消链路不再触发断连；完整心电仍需佩戴并自动完成后再验证波形质量。
- 读取到 9 个手表内表盘；临时切换至 `WATCH911` 后回读确认，再恢复并确认原表盘 `WATCH013`。
- 附近 W8 设备能被发现并标记为 Yuc；没有厂商鸿蒙 SDK，因此连接按钮不会进入假成功状态。
- W9 本轮连接不稳定，疑似被占用或电量/信号不足；ET488 未取得空闲设备窗口，均保留在补测矩阵。

## 复盘要点

- 连接、同步、电量、测量和表盘必须共用同一串行命令队列，避免 SDK 并发导致心电启动即断连。
- 设备分类必须先执行“名称含 W8 即 Yuc”的明确规则，再走 Vep 广播识别；不能用同一默认能力套两家 SDK。
- 任何旧连接、旧账号和旧设备的异步回调都必须经过代次校验，避免换表或换账号后串数据。
- 表盘切换必须保存原路径、切换后回读，并在测试结束恢复；不以发送命令成功代替设备实际生效。
- 页面结构可以向苹果版对齐，但业务数据只能来自真实接口、SDK 或加密本地库；服务端缺失时保留可解释空态。
- 以后每次修改继续执行：先同步远端、复现并留日志、定向测试、双时区全量测试、真机复测、提交并推送。
