## 缺口、方案及影响

现状：远程关爱按钮只显示未适配说明，缺少成员、邀请、授权和成员数据入口。

本轮复用原项目已核实的关爱接口，新增静态类型 DTO、账号代次保护、原生页面和测试。
关系 ID 只识别关爱关系，健康接口使用被关爱成员 ID；返回的账号敏感字段不得进入页面状态。

成员健康数据只读取服务端允许共享的项目，明确区分空数据、无授权、接口不可用。
不将远程记录写入本机健康记录，不根据普通数值做诊断，不生成波形或虚构趋势。

邀请发送、接受/拒绝、共享保存只由用户点击触发；自动化仅使用合成测试数据。
共享设置读取失败时禁用保存，已有未识别授权项保留，避免升级后意外撤销服务端授权。

## 本轮发现并防止的回归

- 相同邀请 ID 出现相互冲突状态时不展示待处理按钮，避免角标与实际操作不一致。
- 同一关系 ID 对应不同成员时拒绝读取；嵌套账号与被关爱 ID 不一致时不显示错误人的姓名和手机号。
- 共享设置先读后写；保存前再次比对服务端快照，发现其他设备更新则要求重新读取，保留未知历史授权项。
- `403` 不通过兜底接口绕开权限；原始每日行只读所选项目字段，不拿通用 value 充当不同健康指标。
- 血氧、体温的图表序列保留嵌套数据结构；身体成分各字段使用明确单位。
- 同一服务端 ID 下不同记录的原生列表 key 保持唯一；无可信时间不标为“最近”，无效波形点不删除后拼成连续信号。
- 会话失效清除旧资料加载标记，防止下次登录后资料刷新被一直阻塞；邀请处理失败后清理旧按钮并重新读取最新状态。
- 人工查看特大字体截图发现：成员/共享卡片使用含换行符的原生 Button 文本，但其默认仅显示一行，操作说明被截断。已显式开启多行并保持高度自适应，补充静态约束；成员卡片已在同尺寸、同字体下截图复核，姓名、手机号和查看说明均完整显示。
