# 鸿蒙 W8 SDK 2.1.5 接入与真机 QA（2026-09-07）

## 结论

宇诚 W8 鸿蒙 SDK 2.1.5 已接入赛电鸿蒙原生工程，并与原有 Veepoo W9 SDK 共存。应用已完成依赖安装、编译、签名、安装、登录、主要页面、设备扫描和前后台恢复回归；双时区自动化均为 432/432 通过。

本轮现场没有发现正在广播的 W8 手表，因此只能确认 W8 代码路径、协议映射、构建和应用运行稳定，不能把 W8 的真实连接、数据同步、手动测量和运动控制标记为真机通过。这些项目必须在 W8 实表开机且未被其他手机占用时继续验收。

## 兼容处理

W8 与现有 W9 SDK 都内置杰理协议模块。鸿蒙包管理会把短横线和下划线模块名归一化，未经处理时，W9 的 `OtaService` 会误加载 W8 模块并在启动后产生 `SyntaxError`。兼容脚本仅对 W8 私有协议依赖做命名空间隔离：

- `jl-ota` / `jl_ota` → `yuc_jl_ota`
- `jl-rcsp` / `jl_rcsp` → `yuc_jl_rcsp`
- `jl-auth` / `jl_auth` → `yuc_jl_auth`
- `jl_rcsp_op` / `jl-rcsp-op` → `yuc_jl_rcsp_op`
- `jl-rcsp-util` / `jl_rcsp_util` → `yuc_jl_rcsp_util`
- `ecg_analyze` → `yuc_ecg_analyze`

`bmpconvert` 两套 SDK 含有同名原生库，继续隔离会造成重复 `.so`；因此统一解析到现有 W9 SDK 的 1.1 版本。

官方 W8 SDK 声明了普通三方应用不能申请的 `ohos.permission.PERSISTENT_BLUETOOTH_PEERS_MAC`。兼容包移除该权限，并关闭只依赖该权限的可选持久设备 ID 门面；SDK 继续使用本地 Preferences 与 BLE 扫描恢复设备，不影响本轮可用连接路径，也不会每 20 秒输出一次权限错误。

## 已接入功能

- W8/W9 双 SDK 同时初始化、扫描和按供应商路由连接。
- 扫描结果保留 SDK 原始对象，避免用户在扫描尚未结束时点击连接发生对象失效。
- W8 设备识别、去重、信号强度、名称、真实地址和 UI 标识。
- 连接状态、电量、设备信息、能力标记、时间同步、查找设备。
- 登录账号与绑定设备所有权校验、自动同步、自动重连和账号切换隔离。
- W8 历史健康数据读取和标准化。
- 心率、血压、血氧、呼吸率、体温、血糖、尿酸、血酮、EDA、血脂、HRV、PPG、压力及心电手动测量路由；仅在设备能力标记支持时开放。
- W8 运动类型固定使用 SDK 2.1.5 协议值：跑步 `0x0F`、步行 `0x10`、骑行 `0x03`、徒步 `0x1B`；不会误发跳绳 `0x06`。
- 设备设置、断开连接、手动测量与运动记录全部按当前连接供应商路由，原 W9 路径保留。

## 已知限制与后续验收

1. 准备一台已解除其他手机连接、可正常广播的 W8，逐项验证扫描、绑定、重连、电量、时间、全量同步和断开。
2. 逐项核对 W8 实表能力标记与手动测量按钮；记录 SDK 原始回调、佩戴状态、终态值和服务端上传结果。
3. 验证跑步、步行、骑行、徒步在手表端打开的运动页面与 App 完全一致。
4. W8 表盘通道暂不开放：官方 W8 表盘栈与现有 W9 表盘原生库有独立兼容风险，需取得明确设备型号、分辨率和表盘资源后专项接入。
5. W8 身体成分和血液成分未在 2.1.5 对外命令中确认，当前按不支持隐藏，不能用模拟值代替。
6. 真实 W8 验收通过后，再用正式发布证书生成 Release HAP/APP 并做覆盖安装、权限和隐私清单复核。
